# Exchange-X 连续恢复超差定位

在本次重放的 checkpoint 上，已定位到可复现机制：**恢复起点的模型、优化器和私有状态值一致，默认 NPU 反向计算仍产生微小梯度差异，随后参数与私有状态轨迹逐步分离并超过原门槛。** 开启确定性算法后，两次独立恢复连续 8 步逐位一致。该结果支持确定性运行策略作为修复候选，但尚未建立全部 Exchange-X 候选的恢复资格，也未定位到唯一的底层 CANN 算子。

依据：[原载荷离线检查](evidence/pilot-r2-x-offline-diagnostic.json)、[受限重放及终态审计](evidence/pilot-r2-x-replay-diagnostic.json)、[第二轮审阅](pilot-round2-assessment.md)。原 `atol=1e-5, rtol=1e-4` 保持不变；原失败载荷和判定保留。

本次选用 `screen-x-lr0.001-s20261120` 的第 257 步 checkpoint：Exchange-X d64、B8/L64、FP32，种子 20261120、LR=1e-3。六条新进程轨迹均从同一 checkpoint 开始，在物理 NPU 5、CPU mask 88–95、8 线程下各执行全局步 258–265。每个设置的 a/b 两条轨迹相互比较，结果如下。

| 设置 | 原门槛内的更新 | 五类张量全部逐位一致的更新 | 首次超差全局步 | 第 265 步私有状态最大绝对差 |
|---|---:|---:|---:|---:|
| 默认模式 | 2/8 | 0/8 | 260 | 0.00138092 |
| `torch.use_deterministic_algorithms(True)` | 8/8 | 8/8 | 无 | 0 |
| 默认模式，D 区域 `second.bias` 当步梯度置零 | 2/8 | 0/8 | 260 | 0.000413895 |

五类张量为模型、优化器、私有状态、logits 和裁剪后梯度；确定性对照中输入、RNG、数据游标、步数、reset、结构和整数检查也一致。**表内确定性结果是两条新轨迹之间的一致性，不是对旧的非确定性参考轨迹重新判定通过。** 三组均有额外观测和 CPU 快照开销，不用于比较吞吐。

恢复值一致有两层证据。原六个 Exchange-X 初筛任务的加载摘要、身份和契约均匹配；在恢复后的第一个更新 258，logits 和私有状态均与原参考逐位一致，但梯度已经出现细微差异。本次又在六条新轨迹中重新计算了加载后的实际存活对象摘要，全部匹配 checkpoint。默认模式的两条独立新恢复仍从第 260 步超差，说明原进程的热状态或 checkpoint 值加载错误不足以解释这一现象。摘要校验以值为主，原记录未完整绑定 stride、存储别名和 NPU 格式；新诊断补记了选定参数的布局，未据此宣称所有后端隐含状态都已穷尽。

最直接的定位证据来自第 258 步：固定同一个前向图和 loss，清空梯度后连续执行两次 backward。默认模式下只有以下两个最终参数梯度出现差异；logits 梯度及记录的 15 个区域评分梯度均逐位一致。确定性模式下重复 backward 的全部检查均逐位一致。

| 参数 | 默认 a/b 两次探针各自的最大梯度差 |
|---|---:|
| `embedding.weight` | 3.72529e-9 |
| `core.receive.embedding.weight` | 9.31323e-10 |

冻结的 [worker 初始化](../.local/pilot-r2/frozen-v2/source/pilotlab/worker.py)设置线程、设备和随机种子，没有启用确定性算法。保存种子与 RNG 可以重现随机选择，不能单独约束并行反向累加的顺序。静态检查发现两处可疑路径均涉及重复索引：外层 `[8192,64]` token embedding 同时绑定输出线性层；[SourceEmbedding](../.local/pilot-r2/frozen/foundation/src/tide/reception.py)通过 `weight[indices]` 取得来源嵌入，区域内共享条目会被多次引用。当前观测点是最终参数梯度，没有固定这两个索引输出处的上游梯度，因此尚不能区分索引梯度累加、上游归约及绑定输出层各自的贡献。

漂移的一个放大路径是区域评分器的 `core.regional.*.second.bias`。原强失败样本的第 258 步，终端区域该 bias 的梯度最大仅约 8.24e-10，Adam 分母约 1e-8、接近 `eps`，对应梯度更新项约 2.60e-5；实际参数变化还包含权重衰减。这是单条参考轨迹的更新量，不能当作两条轨迹之间的差值。置零 D 区域当步 bias 梯度后，第 265 步模型最大差从默认对照的 1.71e-5 降至 9.87e-7，但私有状态仍在第 260 步超差，说明该路径并非唯一来源。

这个置零干预保留了优化器历史，且不能作为保持原局部语义的代码修复：虽然普通固定总量分配对共同 score 平移具有数学不变性，[当前分配器](../.local/pilot-r2/frozen/foundation/src/tide/allocation.py)在无约束总量恰好落在总量边界时按 slack 分支定义 VJP。本诊断只核对了总量上下界相等，没有记录上述边界相等情形，不能据此删除原语义中的梯度。

离线载荷还明确了原失败的程度。弱失败 `1e-4 / 20261120` 在第 264 步只有 `/memories/12/K/keys[4,7,92,58]` 一个元素超差，对应 L3/p1/D 区域的节点 76；绝对差约 1.38022e-5，原允许值约 1.34240e-5，仍应保留失败。强失败 `1e-3 / 20261120` 在第 260–265 步的私有状态超差元素数依次为 41、18、115、860、31,404、92,736，第 265 步最大差为 0.0107536。两侧在第 261、265 步均按流边界 reset，不能将其简单归为旧 cache 未清理。176 组已记录 KV 正值/零值支持比较一致，但这些记录不覆盖全部内部路由支持。

用户授权上限为一张空闲 NPU、600 秒设备执行、六条轨迹各至多八次更新。实际六条轨迹全部执行完成，共 48 次诊断更新，设备执行 122.30 秒，队列总时长 128.92 秒；这些重复诊断更新不计入原轮次学习曝光。进程树采样 RSS 峰值 2.45 GiB，诊断输出 5.01 GiB。服务 `tide-pilot-r2-xdiag-20261119.service` 已为 `inactive/dead`、`MainPID=0`、退出成功；七个记录进程身份消失，cgroup 无成员且已移除，队列 manifest 和协作锁已释放。诊断脚本、启动器、checkpoint、原任务、冻结身份、原调度记录和 Shannon 预检证据哈希均通过核验。

本次新增的是执行与恢复机制证据，没有新增学习效果或性能结论。诊断只覆盖一个 checkpoint、种子、学习率和设备组合；没有重做全部六个 Exchange-X 候选的资格检查，也没有验证 FC-K 或 Shannon 的根因。原第二轮 70 项执行完成、2 项接续被拒绝、7 项八步恢复超差及 Shannon 预检父段第 13/14 步超差均保留。

后续对齐建议是将确定性与精度策略显式写入运行及 checkpoint 契约，再在新版本中验证相关候选的恢复资格；如果需要算子级归因，可优先用固定上游梯度隔离 SourceEmbedding 的索引反传。当前未安装实现修复，未启动第三轮或后续队列。原轮次和本诊断的输入、checkpoint 与失败载荷继续保留。
