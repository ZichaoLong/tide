# 当前 NPU：tiled 与 auto 融合路径的有限成对性能测量

本次在同一张排队分配的NPU上，以FP32、4个主机计算线程比较当前冻结基座。所有测量已结束；没有改变auto分派或训练源码，没有恢复A/B。机器记录见[审阅JSON](evidence/pilot-r3-attention-performance.json)。

## 完整训练更新

三个样本均为d64、batch=2、sequence_length=128，每次从相同的已训练模型/Adam/private state和固定基准RNG出发，重复同一步。2次预热后交替测量7次，表中为中位数。计时包含输入传输、前向、loss、反向、裁剪和Adam，排除状态重载及健康采样。

| 样本 | auto 单步 | tiled 单步 | tiled 耗时增加 | auto / tiled token/s |
|---|---:|---:|---:|---:|
| FC/K d64 | 104.5 ms | 112.8 ms | 8.0% | 2450.5 / 2268.9 |
| Exchange/X pool d64 | 682.1 ms | 731.3 ms | 7.2% | 375.3 / 350.1 |
| Settle/K singleton7 d64 | 1167.8 ms | 1306.9 ms | 11.9% | 219.2 / 195.9 |

本次三个样本全量切换attention后，整步耗时增加7.2%～11.9%，吞吐下降6.7%～10.6%。记录到的attention调用形状/次数、实际Full执行与参数活动量一致。auto实际调用均为native；tiled使用基座普通/质量缩放分块反传。原始work对象还含logits健康浮点量，Exchange/Settle这些量有差异，已在原始比较中保留；活动量核验仅排除health字段。

## 单 attention 接口

下表计时含公开weighted_attention接口的分派、先验和mask处理，并非只测CANN内核。每种模式预热5次，再交替执行5个窗口，每窗口10次，计入窗口结束同步。形状为独立batch B、head H、query Q、key K、每头宽度D。

| 输入 | B,H,Q,K,D | 前向 auto / tiled | 前向+反向 auto / tiled | 前反向耗时倍数 |
|---|---|---:|---:|---:|
| one-key | 2,1,128,1,64 | 1.130 / 1.933 ms | 1.683 / 4.718 ms | 2.80× |
| one-visible-of-five | 2,1,128,5,64 | 1.047 / 1.891 ms | 1.643 / 4.803 ms | 2.92× |
| five-key | 2,1,128,5,64 | 1.095 / 1.922 ms | 1.710 / 4.868 ms | 2.85× |
| sixteen-key | 8,2,128,16,64 | 1.111 / 1.933 ms | 1.708 / 4.855 ms | 2.84× |
| causal-b2 | 2,2,128,128,64 | 0.417 / 1.496 ms | 0.744 / 3.507 ms | 4.71× |
| weighted-causal-b2 | 2,2,128,128,64 | 1.063 / 1.942 ms | 1.651 / 4.812 ms | 2.92× |
| weighted-causal-b32 | 32,2,128,128,64 | 1.083 / 1.976 ms | 1.668 / 6.084 ms | 3.65× |

前向tiled耗时为auto的1.71～3.59倍，前向+反向为2.80～4.71倍。causal-b2为无显式可训练先验；其他组使用正的可训练先验。完整模型还包含投影、FFN、状态运算、词表输出、loss和优化器，所以局部算子的倍数不能直接换算整步速度。

## 边界与释放

这些是有限耗时观测，不是数值认证。所有本次成对抽样满足原atol=1e-5/rtol=1e-4，但这种容差无法替代单支持精确零导数恒等式；此前NPU融合反例、Shannon恢复超差和其他数值问题继续保留。更宽模型、更大batch、共享NPU及只回退单支持分支的整步开销尚未测量。

本次只使用一个NPU worker，物理可见卡9；设备时间60.423519秒，处理15360个重复基准loss token，无正式学习曝光。四个记录进程身份、cgroup和队列均已释放，冻结输入检查通过。全周期借记73.936169/7200 NPU小时。

通用训练终态审计保留1项“completed result无checkpoint”的incomplete发现。本计划是丢弃更新的固定状态性能测量，不生成接续checkpoint；该预定范围与完整结果另在审阅JSON核验，未伪造checkpoint或覆盖原审计。
