# v6：局部候选覆盖与实质规模训练

2026-11-09用户已授权实施。共同目标是同一个模型的自然文本next-token质量、实际稀疏和局部结构，并检查数据、参数和依赖深度增长的收益。此次取代此前仅补512步的建议；旧v5结果、失败、依赖身份和费用封存。两条研究线并行，规模训练不等待全部筛选结束。

## 研究表与判据

实施清单为182个局部配方实例（91个具名候选各在FC/HB承载）和2个近参数小Transformer控制，共184个筛选配置；规模线14条。原10个静态非法控制配置及下载读取超时分别保留，修正/续传使用新身份。Transformer控制的实际参数按任务模型公式及实例化双重核对。

所有候选先做实际拓扑/局部模块/宽度/后端的B2/L3独立检查，再用真实训练数据进行三个新进程的三步恢复比较。稀疏路径不要求每个区域在微输入上均激活，但保留逐区域梯度/消息，要求输入和图梯度真实连通；原严格阈值不变。通过后才进入学习。覆盖及规模分别固定全局独立样本batch，按实测选择物理microbatch及累积；token日程、里程碑和训练目标不随设备改变。

规模线保留相同token前缀与token学习率日程；Transformer获得同等级有限调参机会。较大模型若未能利用更多数据，保留负面/无结论结果。多配置筛选使用validation；test仅在候选和分析冻结后由独立评价读取。第二种子与筛选晋级需在本轮剩余明确预算内具名列出，不自动扩成全组合。

## 资源与停止

新活动共同墙钟上限48h，从首个v6计算作业开始记录绝对截止，不继承旧22:49截止。上限1536 CPU核时、384 NPU卡时，分别计账；CPU上限包含NPU训练的主机线程占用预留，不将不同资源小时相加成性能指标。最多128个CPU筛选worker，含主机辅助最多192个CPU线程、12个NPU worker；先64个CPU再按实测吞吐/内存提升。公共设备可共享，无空闲/FIFO否决，但保持账号设备生命周期锁、实测余量与background.slice。

新增磁盘≤120GiB，账号硬配额800GiB，至少保留160GiB可写余量；总主机RSS预算768GiB，保留至少512GiB系统可用内存作为新准入条件。每个子任务有timeout/RSS限制，失败后不无限重试。达到时限/额度保留最后已发布checkpoint；停止与恢复使用新输出及完整状态身份，不覆盖现有运行。

校准只决定后端/microbatch与可承载范围，不要求NPU比CPU快才允许独立探索，也不将小模型的CPU优势外推到大模型。有效batch以实测和学习目标决定；累积与物理microbatch分别记录。若执行速度限制百万token训练，应形成具体公共需求，同时推进不依赖该缺口的候选。
