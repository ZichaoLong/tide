## 联合问题

在自然文本的连续next-token预测上，TIDE能否达到接近可靠对照的语言质量，同时展示可扩展容量、实际稀疏和有界局部交互？
这些证据必须来自**同一模型、同一checkpoint和对应评价数据**。不能把A的合成检索稀疏与B原模型的语言能力拼接成联合成立。

检索/复制任务保留为机制诊断。Agent可以组织规划、检索、工具和多次调用；系统评价另计调用/token/工具/时延预算。
本表不扩成细分能力清单或agent基准，模型本体优先承担可用的语言预测、上下文利用和生成。

## 共同数据与评价（TL-LM0）

- 首选`Salesforce/wikitext`的`wikitext-2-raw-v1`，小型英文自然文本。已固定revision `b08601e04326c79dfdd32d625aee71d232d685c3`并完成来源、文档边界、划分及精确重复审计；锁与实际范围见[数据记录](../evidence/language-data-ready.json)。近重复及预训练污染仍未知；不边看test边改配方。
- A/B共享原始文档和split manifest。A只用训练文档拟合4096 BPE；B保留固定Qwen tokenizer，原始文本不套聊天模板。保存tokenizer身份、BOS/EOS和规范化规则。
- 语言loss覆盖全部有效目标位置，明确`x[t] → x[t+1]`、padding和文档mask。首个窗口为128输入位置，接入先用32位置。每文档分块，块开始重置状态，末块padding屏蔽；不跨文档传播状态或loss。每次更新重置应用状态，块内完整BPTT。本表不认证长上下文或跨更新持久学习。
- 评价用固定无重叠分块，每个目标计一次，保存有效token、原始字节与上下文长度分布。validation用于筛选及预登记checkpoint选择，test只在配方冻结后评价。有界包可选固定文档子集，但必须在训练前锁文档ID/hash，并报告覆盖范围和不确定性。
- 主指标为有效token加权NLL（nat/token）和同tokenizer PPL。**拟定质量容差ΔNLL≤0.05**，相当于PPL增幅≤5.13%。这是新语言研究的预登记建议，不是既有通过结论或数值容差。先导看点估计；正式非劣判断要求独立test文档配对bootstrap单侧95%上界≤0.05，并单列种子变化。区间不能区分时记无结论，不事后放宽。
- A/B词表、上下文和预训练背景不同，**不直接横比PPL**。如补充BPB，须统一原始字节覆盖、边界和上下文口径。固定prompt生成、前缀打乱/截短用于有限诊断，不替代主指标。

## A：从零训练完整语言模型

实验侧实现embedding → 公共HB/core-5 → 每位置公共readout → tied LM head和bias，全部任务参数从零训练。
稠密/稀疏形状和初值对应，仅改分配正则器，保持同一regional_total预算。允许端到端loss与统一optimizer，不能称局部学习规则。
小Transformer使用同词表/窗口/文档/token暴露/逻辑更新。首选3层、width96、4头、FFN384、pre-LN、GELU、固定sin位置、dropout0、tied head及bias；标准有偏投影的静态估计733,024参数，比HB16全LM多9.53%，目标偏差≤10%，实例化后核对并冻结。
两者hidden宽度与参数分配不同，属于架构比较；若质量有差距，不能直接归因稀疏，须先看同架构dense/quad对照。
实际活跃计算和墙钟另列，不能声称同时精确匹配参数、计算和时间。

“差不多”相对该小尺度、该预算的普通LM，不要求本机从零立即追平预训练Qwen0.5B。
若普通LM明显欠训练、模型未利用上下文或只有训练loss下降，不宣布语言可用性成立。
报告学习曲线、相对训练语料unigram及上下文破坏控制的增益和生成例子。
只有需要区分“学到选择”与“单纯少发送”，且公共契约有合法实现时才加固定稀疏对照；不在实验侧拼执行核心。

## B：利用已有语言能力，让模块承接实际计算

复用缓存`Qwen/Qwen2.5-0.5B-Instruct`，revision `7ae557604adf67be50417f59c2c2f167def9a775`、原tokenizer/head。
理由是已有约943MiB权重、当前栈已有运行证据、无需新大模型；其预训练和指令后训练背景单列。
自然文本基准仍需新校准，旧查表test229/256不是语言NLL验收。

固定**最后decoder MLP**一个位置，输入为其原归一化hidden，覆盖全部有效token；其余骨干/head冻结。
保留原残差结构，用`(1-alpha)·原MLP(x) + alpha·TIDE(x序列)`承接该MLP输出。最终目标为alpha=1且推理跳过原MLP。
alpha=0只用于初态/状态投影检查；影子MSE用于接入和信息诊断，固定10%混合不再作为主完成标准。
只有混合时接近而完整替换失败，就记“部分承接，完整替换未成立”，不改成功标签；不自动扩大多层替换。

建议固定日程：总更新前10%学习教师MLP输出MSE；后90%用语言CE，其前25%将alpha从0.25线性升至1，之后固定1。
确切整数更新、学习率、batch和token数在吞吐先导后冻结。教师调用、影子暴露、过渡期双分支计算都计入成本。
原模型继续训练仅训练同一原MLP，总训练token/逻辑更新与替换候选相同，始终用CE；明确loss配方与可训练参数差异。
简单MLP替换采用同一影子/过渡/CE日程。
HB16 width32及无偏896→32→896投影静态合计591,412可训练参数；无偏896→330→896、GELU简单MLP为591,360。
这是拟定对照，实例化后仍须核对，不把宽度或架构变化后的旧权重载入称精确resume。

hidden信息及32维压缩可能限制承接，有限线性/PCA诊断不能给所有非线性模型上限。
B不以学会新符号能力为必要条件，重点是利用并保持原能力来检验TIDE。
一个MLP完整替换仍保留其余Transformer全局注意力、词表head与预训练成本，只支持**局部子模块**结论。
关闭分支只证明已训练模型依赖它；架构价值还需原模型继续训练和简单MLP替换对照。

规模趋势至少需要16与40两个真实训练点：固定局部边界，报告质量、工作/内存增长相对容量增长的比值或弹性，不外推无限规模。
该阶梯同时改变容量、区域数与路径深度，只支持此HB配方的联合趋势，不能独立因果归因参数容量。
全模型近恒定活动、长上下文常数内存、多设备效率仍是后续问题；语言未接近时结构结果可以有信息，但联合目标保持未达/未区分。

## 接入、测量与预算

现有`Core5Encoder.run_features`返回各位置公共结果，`forward`只读最后位置。全位置readout/head/loss属于实验侧，不存在必须等待的“公共全位置输出缺口”。
新路径检查因果前缀、目标移位/mask、输入和共享参数梯度、唯一optimizer参数、更新、文档/更新状态清理以及新进程恢复。
A/B分别比较prefill、分块和逐token续接的同模型logits/状态，沿用严格数值与离散阈值。固定16个validation前缀、greedy生成32 token，用于推理状态/成本和有限生成诊断，不能代表广泛语言能力。
B另查alpha=1原MLP零调用、初态保持与分支干预。旧单位置恢复不认证新序列路径。

分列**执行、严格数值、离散语义、恢复、学习、性能**六轴。保留各项原严格阈值和失败；第四批atol1e-5/rtol1e-4的full/cache失败不会因质量容差改变而通过。
有界定位及机制检查后，可在NPU FP32继续标记的有限数值探索；不要求消除全部浮点差异，也不将A限于CPU FP64。
非有限、非法配置、因果/共享梯度/状态错误、离散不变量或所声明精确恢复失败停止依赖路径。
路由/支持差异及实际工作必须记录，不能用于同模型等价加速声明；正式训练不逐步跑CPU参考。

batch不继承B2 smoke或旧B128：每路线先L32测试B8/32/128，容量/时限允许且吞吐仍增长时最多加一个更大B；再L128确认选中B，必要时一次减半。
每点1次warmup+2次同步更新，单点≤180s，并受阶段总额约束。记录独立样本B、microbatch、accumulation、有效token及实际算子形状，序列位置不能充当B。
按吞吐与足够更新数选择；平台期取达到最佳观测吞吐90%的较小B。达到有界校准上限而未饱和时照实记录。
CPU/NPU按端到端完成时间、内存、数值策略和排队选择；正式配对同后端/精度。优先独立候选并行；单模型DDP/native/resident多设备资格不能假定。

**拟议下一执行包**：一个12h共同墙钟（含排队、恢复、记录），累计≤8NPU小时、≤2CPU-only worker小时。
最多同时2张真实空闲NPU，每worker≤4CPU线程/24GiB，整体≤8线程/48GiB；CPU准备也占此并发资源。
每训练尝试≤2h；失败、重算、初始化、观察和恢复共用总额，不以换ID重置。每个配对启动前预留完整评价、checkpoint及退出时间。
长任务采用共享队列、`background.slice`、只读源码/配置/依赖快照。新增磁盘≤8GiB，800GiB硬配额至少留80GiB写入余量；提交前复核，不清理他项资产。

吞吐先导后按最慢候选锁共同上限：每候选最多1,000,000有效训练token、1,024更新，实际取预算可容纳的更小值。
优先要求≥65,536 token且≥128更新的学习先导；连此下限都容纳不了，交付执行瓶颈，不把几步loss下降当语言比较。
下限不是充分训练认证。大B不能挤掉必要更新数，学习率/日程变化另记配方身份。
规模点和第二seed服从已有候选完整评价，88节点及第二模块替换不在本包。

历史成本提示Python路径可能限制研究：HB16 width16/B32/7位置CPU400步约5108–5652s；B4单位置B128 TIDE约12.82s/step。
这不是width32/L128语言吞吐预测。合理batch仍不可负担时，带实际shape/trace/计时边界向公共基座提出执行需求，不复制核心，也不偷偷退回单答案任务；仅阻塞依赖项。

## 实施时固定的接入与有界调整
