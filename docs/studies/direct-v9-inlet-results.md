# TL-INLET-v9：入口树降低接收，但本轮未改善质量

问题：保持HB主体初始化和输出读出，将原直接入口改成1→4→16入口树，能否减少主体接收并保持质量？
8条入口树轨迹全部完成16M；原入口复用活动组的8条相同种子对照。
树额外21节点（1+4轻量复制、16个区域门控），约1.297M参数；没有改成多层替换或新出口树。

相同131,072目标validation，两seed均值；百分比含padding位置，NLL越低越好。

两个入口树都减少主体接收；R32质量代价+0.1508 NLL，R64+0.0367。
每个seed均同方向，文档配对区间均不跨零（这些区间不包含种子/选择不确定性）。
因此不能只报主体约10%/3%就认定全模型达到目标：计入边界后分别12.41%/5.22%。
实际Full仍稠密遮罩，没有证明边界节省了物理计算或提高吞吐。

稠密Bern入口控制：R32原入口/树4.3900/4.4052，R64为4.3867/4.4032，
接收与Full均100%。R32 seed22单独略好0.0015，区间跨零；保留该反例，
不能把所有树的变化都称为一致劣化。它提示边界本身、选择性接收和相应状态覆盖需进一步分开。

结论：本轮树实现达到了减少主体接收的结构目标，没有展示质量或总活动优势。
未区分的解释包括入口信息瓶颈、门控训练、局部到达覆盖、额外参数及整体活动差异；
不能据此断言所有入口树不可用，也不能默认延长训练会修复。
迁移时需保持主体编号/初始化、token等效时间与记忆窗口并计入所有边界节点；公共完整执行资格另验。
建议在下一批有限修改入口覆盖/表示时保留原入口与Bern树控制；本轮不自动续训。
