# TL-C — 共用任务已落实，跨路线架构胜负尚无依据

两条路线共用8键/8值、4关联、2延迟的任务分布、映射级互斥划分、CE/accuracy和干预口径。A1正式确认使用validation/test各256；先导使用validation128且不启用test。每个比较内部固定样本，不能将不同评估规模或不同训练暴露的数字直接排名。

| 路线/配置 | 参数来源与可训练参数 | 暴露与配方 |
| --- | --- | --- |
| A FC | 从零，68,722 | 正式B32×400，AdamW，CPU64；另NPU32×80探索 |
| A HB | 从零，两候选均136,252，初值相同 | B32×80，AdamW，CPU32 |
| B 原模型 | Qwen预训练及指令后训练 + 新分类头，494,039,944 | B32×40，SGD，NPU32，骨干全训练 |

已审阅结果分别见[FC](TL-A1.md)、[NPU](TL-A1-NPU.md)、[HB](TL-A2.md)、[生长](TL-B1.md)。A的正式检索成功不能据此宣布胜过预训练架构，因为参数、既有训练、优化器、更新数、设备和额外工作不同。B接入成立也不能认证完整TIDE的从零学习或HB稀疏收益。

可迁移的条件经验：在相同任务、KV/read语义、完整episode BPTT和状态重置边界下，可优先尝试FC→小HB；实际HB已经重新检查，得到历史利用及工作减少信号，但尚未达质量门槛。中性残差初始化、梯度和同栈恢复方法可在相近接入中复用，质量/速度须独立验证。CPU64和NPU32短程汇总曲线接近，只是学习观测，不解除严格数值失败。

首批没有新增跨路线权重迁移、蒸馏、块替换或真实语言任务桥接。结论是共同评价基础已建立，而广泛架构价值、组合成功与跨任务迁移尚无支持。下批优先解决HB质量门槛和B实际贡献，两条线保持各自证据边界。

第三批增量：HB400步在三个seed和共同2048唯一映射上均学会检索，稀疏约少45%的Full/消息，但质量低0.146–1.758个百分点；这是当前CPU FP32小HB的新增直接证据，原80步结论保留。B的三个200步对照仍未达25%门槛，缺失的TIDE候选正在修复启动故障后补做。路线间参数来源、可训练参数、12,800/6,400例暴露、AdamW/SGD及CPU/NPU差异仍在，不从两条线分别成功的接入检查推导架构胜负或组合迁移成功。见[第三批进展](third-batch-results.md)。
