# TL-LM-SCALE：规模与多区域仍未检查

问题：保持局部宽度/区域/端口界限时，增加容量能否获得语言收益，并保持可接受实际活动增长？

原计划：HB16→40→88为静态候选；HB16全位置先导时限失败保留。LM-ADJUST-001改为FC4起步、条件FC8双区域。LM-ADJUST-002明确先完成七候选语言比较，不自动启动FC8或第二seed。

实际结果：只有FC4（4节点、1区域、0内部边）的一个真实语言训练容量点。FC8尚未训练，跨区域消息、质量/容量曲线和规模趋势均**未检查**；其静态参数/边数不能充作学习或性能证据。当前FC4的约一半Full事件不能证明规模扩大后总活动恒定。

解释边界：A/B在不同预训练背景下各有质量/稀疏结果，不能拼成两个规模点。改变FC depth会同时改变参数、区域、内部边和路径长度，未来即使两点成立，也仅支持该配方的联合趋势，不能独立因果归因于参数量。

建议选项：完成语言对照审阅后，以固定width32/region4及相同曝光比较FC4/FC8。先复用合法接入证据并补受影响的小型多区域/恢复检查，以真实预算限定完整配对；不要要求稀疏取得同比例硬件加速。可申请上限4NPU小时/最多2卡/12h共同墙钟的新有界包；估计来自FC4实测和额外检查余量，FC8成本仍未知。当前没有提交此选项，等待用户验收与下一批决定。
