# TL-B-LM v4：同32维瓶颈对照的限定结论

问题：此前TIDE落后于参数量接近的简单MLP，能否只用32维入口的信息压缩来解释？本批仅增加一个同32维入口、参数接近的稠密分支，保留原先所有权重，在提前冻结的16份新确认文档上比较。

**结果：TIDE优于新增同32维对照，但仍落后于入口106维的简单MLP。** 这使“hidden根本不包含可用信息”不足以解释全部差距；结果与入口压缩、局部变换和优化共同影响相容。本次没有把瓶颈维数、模块形式、序列状态和优化路径完全隔离，不能认定某一个因素是根因，也不证明TIDE的普遍架构优势。

新对照为896→32(tanh)→2080(GELU)→32→896、无bias，train-only归一化和零输出初始化；与旧替换候选相同B8/L32/seed11、13步MSE+115步CE、alpha最终1、32503训练目标。旧train/validation张量、顺序及cache保持，未重复训练旧候选。确认集4096目标，A/B各用自己的词表，不跨路线比较NLL。

按原文档配对bootstrap（20000次，单seed条件下的描述性区间）：

- dense减同32维稠密对照：−0.084795，双侧95%区间[−0.102046, −0.068481]；sparse减该对照−0.073620。
- sparse减dense：+0.011175，单侧95%上界0.019523＜原0.05容差。Full事件16384→8335，减少49.13%；candidate/Upd/Read不变，单区域、零内部消息，不等于总FLOPs或吞吐减少49%。
- 新对照减冻结基线：点估计−0.021640，但单侧95%上界0.055677＞0.05，**未通过预设的确认集非劣筛选**。不因点估计略好而改判通过。
- TIDE sparse仍落后简单MLP0.092769、原MLP继续训练0.585139；后者可训练参数多约68.5倍，不是同参数量对照。

六轴分别记录：执行全部完成，07:04:35北京时间终止、实际cgroup及已知后代清空；因果/未来VJP为零、两步后输入与所有权重梯度进入、唯一optimizer参数、alpha0精确保持和alpha1原MLP零调用通过。独立CPU FP64公式与手算VJP通过；NPU有45个权重梯度元素在原atol1e-6/rtol1e-5下有限超差，最大约2.37e-6。训练后完整/cache在原atol1e-5/rtol1e-4下20391/2430976元素有限失败，最大1.33e-4，所测argmax一致。未知原因保留，不视为严格等价，也不把任务效果覆盖这些失败。
