## 并行、临时存储与真实算子归因

[FC三层调查](evidence/fc-three-layer-comparison-20261111.md)在软配额剩约8GiB时复用现有环境/构建，
将约1.3GiB临时固定源码和大型profile放项目独占shm；小型日志、配置、终态和审阅摘要持久保存。
CPU/NPU在不同CPU池并行，存储没有成为瓶颈。软/硬配额、文件系统余量、tmpfs和主存可用量分别检查；
tmpfs须共同计入RAM预算，不充当持久证据。真正限制必要写入/并行时明确报告，不静默缩小任务，
不清理外部仓库或共享工具链；这种处理不规定所有任务都必须用shm或特定并发方式。

同一调查分别记录自然完整区间、阶段同步及独立profile。自然计时的host phase不能当设备阶段时间；
小profile只定位机制，不能按比例分摊大窗口全部差额。ATen嵌套调用、独立autograd节点、kernel和
厂商Free时间各有含义。实际NPU导出中operator device-duration全零、存在停止RECORD警告，
即使有最终同步和optimizer事件也必须保留这些观测限制。

## 从设备利用率追到实际反向算子

[REQ-006四代表](evidence/req006-diagnostics-20261112.md)中，HB88已使用节点×B×L的bmm，
但704个AICPU kernel全部可沿device flow → `aten::ge` → `ClampMinBackward0` →
前向sequence number追到浮点`clamp_min`。同名GreaterEqual的其他实例运行在AIVEC；
不能仅按kernel名称或整数时间猜测设备归属，也不能将AICPU当成host fallback。
设备区间累计、区间并集、主机inclusive范围与无插桩完整步分别记录，不把累计秒数当作可省wall-time。

可复用处理是先复核具体Scalar/Tensor重载和反向生成的算子，再用独立公式/VJP、相等边界、
非有限分类及同shape算子诊断判别替代方案。`diagnose_scalar_floor.py`固定常量构造在计时外，
比较同dtype/device的Tensor阈值；不能换用相等处导数为1/2的`maximum`，也不能顺便更改floor数值策略。
局部CPU等价不证明NPU避开慢核，原下游冻结实现与其独立验收仍分别维护。

[后继常量实测](evidence/req006-floor-20261112.md)中，原Python float Scalar约5.972ms且有2个AICPU，
显式FP32表示的Scalar/Tensor约0.263/0.298ms且无AICPU。但原float阈值与FP32阈值不同，
相同前向值在边界仍可产生不同VJP；这既不是“Scalar必慢”，也不是可无条件采用的等价替换。
原有限失败保留退出1并另采成本，非有限仍拒绝；共享单点不外推整模型收益。

同一报告的measure/profile虽同seed与输入，独立prime后的权重hash却不同。跨进程配对应比较
实际初态，包括optimizer槽和RNG；需要严格同材料时保存并复用固定初态，不能凭seed推断。
原trace成功导出但解析失败的作业保持failed，离线恢复解析单独记录，不补写未记录的步骤或恢复资格。

## 模式缺口、实际位置和阶段差额

[FC16/LH既有记录换算](evidence/performance-accounting-20261111.md)没有重跑性能：
FC16密集输入为B×L=1024，LH的B4/P16不齐输入只有61个实际样本位置；端口消息不能重复计token。
当前LH训练、历史1B/9B推理和原LH含grad前向来自不同源码/配置，不能拼成一个三模式对照。
默认FC与直接公式的完整训练差额主要位于核心前向/反向，但两者都有区域分配；
小图中某个阶段较慢不足以把完整差额归到该原因。报告对应阶段差额及剩余量，
将单侧诊断、接口假设和因果上已隔离的增量分别标明，才能选择真正有区分力的下一项比较。

## 先核对解析后的执行配置

[554f2f5有限代表](evidence/interface-heads-performance-20261110.md)的首版driver把site放在各case内，
公共matrix级site覆盖为空，导致12个native/SDK配置在计算前拒绝。后继只补未执行项，运行前
先纯解析并核对实际库路径/构建身份。请求JSON里出现路径不证明最终执行使用了它；
生成器、matrix覆盖层与冻结resolved配置各自有契约。原启动失败、成功成本、独立数值和
精确恢复分别保留，不能为外层passed重跑全部成功项或把无测量行的拒绝算作性能退化。

## 配置覆盖与证据的校验

[f456160修正资格](evidence/core5-coverage-correction-20261030.md)没有新性能数据，记录以下可复用的设施经验：

- 用例名称不能证明结构覆盖。原FC depth=1没有层间边，mixed也没有中间模块；新增断言检查实际边、rank、模块族与执行事件，再验证完整训练和恢复。
- 全图配置不能取第一节点代替。KV窗口可能同时含0和非零，来源分类也不同于参数共享；从所有节点/区域生成分组事实，并用独立预期值校验关键配置。
- 正确性与性能须分别记录且限定源码/配置。JUnit中的实际检查可以生成覆盖记录，测试耗时不能变成吞吐；旧汇总不能拆成未记录的逐配置通过。
- 历史错误应保留并更正范围。旧24项通过计数仍成立，但不认证多层FC/FC混合；新52项资格不追溯提升旧源码或大尺度/设备结果。

## 下游安装与恢复的验证边界

[e17f9ea安装消费者资格](evidence/downstream-contract-20261030.md)是工程/正确性证据，没有性能增益结论：

- 同进程新owner恢复不等于新进程恢复。小型FC/KV FP32的native workers2在独立两步对照后，跨进程仍有输入/参数梯度与SGD槽逐值差异；只关闭autograd多线程没有解决。worker1是另一显式配置，不称原问题修复。
- 线程与反向引擎策略也属于执行身份。修改packing、共享计算或并行构图后，除完整梯度核对外还需验证真实应用的跨进程恢复，不能只看最终参数或loss。
- 图checkpoint与应用恢复分层。head、optimizer、scheduler、数据进度及各RNG由实验组合保存；小文件整体CPU副本示例不能作为大模型分片方案。
- 安装物hash证明字节相符，构建记录证明Git来源。复制消费者到源码外并验证实际import路径，才能发现开发目录意外提供的依赖。
- 上游交付与下游验收分别维护。共享修复可服务多个实验，各实验仍须验证自己的配置和任务，再显式升级依赖锁；负结果保留原身份和严格标准。

## 失败经验与临时产物的生命周期

- 一个正式Git归档约38.5MiB，反复收入每次完整源码快照会积累大量重复存储；本次214份旧源码tar共约10.47GiB。固定源码的运行记录可保留commit/hash，任务结束后依授权退役临时快照。脏源先保留实际差异，不能用一个HEAD代替。
- 失败现场与失败知识分开保存。两份真实分配失败行合计不足6KiB即可连接原错误和独立Decimal局部回归；完整9B材料无需为这个局部问题长期保留，但它不能替代完整图、反向或训练验证。
- 清理本身检查架构是否依赖历史目录。正式复现入口、安装消费者、源码构建与证据查询应从干净checkout工作；路径失效时修补入口或记录退役事实，不恢复所有旧材料来维持隐含依赖。
- 原始状态退役后只能重新生成/运行，不能由hash补回字节，也不能声称跨环境逐位再现。维护位置与入口见[复现导航](reproduction.md)，任务终态与内部用例结论仍分别记录。

## 终态产物与源码保全

[本次清理](evidence/artifact-cleanup-tracked-only-20261031.md)在保留204条审阅结果及原严格失败后，
将仓库从279.594GiB降至76.410MiB，并释放16.040GiB项目tmpfs。大checkpoint和重复源码副本无需成为下一轮默认依赖；
配置、输入生成器、有界诊断与完整结果身份应先进入Git。重新生成的失败见证不能冒称原checkpoint字节复验。
未提交源码与运行产物分开处理：包先移动到仓库外受保护目录并校验，按用户要求以后再分析，
不因基线提交已合并而认定工作区差异无价值。删除前后通过独立CLI核验归档可查询，不重建环境来证明清理本身。

## 外部语言模型吞吐的可比性

[Qwen公开调查](evidence/qwen-throughput-survey-20261102.md)记录30份来源与83条外部数字，未执行模型。
Qwen3官方分子是输入加输出token；llama-bench的pp/tg分测且排除tokenization/sampling；
vLLM请求数/QPS不等于计算batch，发布基准的dummy权重也不能证明真实权重质量。
同机、同精度、同材料、同返回/计时边界确认前，不把公开吞吐换算成core-5样例窗口速度。
CPU公开线程例中prefill变快而decode变慢；AMX候选decode改善同时有prefill负结果，不能只挑一个阶段。
训练s/it只有在原实际global batch、有效token及更新边界明确时才可转为训练token/s；
当前关联脚本不能追认旧实验配置。支持列表和相对倍率不填成绝对吞吐。
固定config显示1.5B/1.7B相近参数模型可有4倍每token KV差异；按层/头/维度和逻辑B预算，
Hub权重条目计数与共享去重参数也须分开。静态权重+KV只是下界，不代替workspace/恢复峰值准入。
