## 修复范围

基座 `/mi/data2T/zlong/home/llm/graph-execution-foundation` 的 `TideModel._reception_mask` 始终从静态拓扑生成成员掩码，覆盖普通、区域批处理、放置及重计算路径。结构不存在的边没有梯度根；真实存在但质量为零的边保留原右导数。

`ModelConfig.reception_mask_padding` 默认 true。为读取旧 checkpoint，显式 false 仍保留其序列化值，但不再关闭必要的掩码。没有变更参数布局、private-state 格式或 Shannon 数学。先前未提交的 allocation/文档/测试修改按 SHA256 验证原样保留。

修复前基座 `src/tide` 与本批冻结 r04 的对应源码逐文件相同；本次只改了该源码中的 `config.py` 和 `model.py`，另补测试、CLI 说明和文档。实现采用包含工作树内容的不可变快照资格，未提交或推送。原活动/冻结实验副本、数据和环境均未修改。旧 false 配置的有效行为和 auto 后端选择发生变化，源码身份必须在真正接续时显式迁移；精确加载不代表旧、新轨迹相同。

## “大数是否已经污染判断”的直接证据

在失败前最近健康 checkpoint 的下一批次上，旧实现确实出现 **1.5726×10²³** 的有限填充槽梯度。独立 FP64 计算的对应假想梯度约 1.5726574×10²³：这个数并非凭空的随机错误，问题是不存在的边不应有这个导数。

固定双方 Reception 使用同一 tiled 后端，修复前后完整模型的前向、全部真实参数梯度、Adam 更新、优化器状态与 private state **逐位相同**。填充梯度从上述大数变为零；真实 mass 梯度最大约 0.022516，Q/K/V 和真实 mass VJP 逐位不变，且通过独立 FP64 公式。说明该样本中，有限的空槽梯度确实被布线的精确零消除，没有污染真实更新。

换回实际 auto 后端，新旧更新均通过原容差。真实参数梯度相对 L2 差约 4.30×10⁻⁷，参数更新量相对 L2 差约 1.37×10⁻⁵。这个差异包含掩码引起的后端选择变化。

到了原失败批次，空槽假想梯度约 −4.16×10³⁸，超出 FP32 范围，随后 `Inf×0` 产生 NaN。原 worker 在 optimizer.step 之前已停止，因此这次失败更新没有写入模型。这个闭合因果链不能外推为所有此前中间运算都准确。

## 有限值检查之外的剩余风险

本次还复现了另一种机制：**接近零的数值残差被优化器放大**。它不需要大激活或溢出。

在强制 Reception tiled 的健康状态诊断中，三个 Q/K 参数分量的 FP32 梯度约 −1.31～−1.54×10⁻⁹，FP64 对照约 10⁻¹⁸～10⁻²⁰；对应旧 Adam 一、二阶矩均为零。经过原 `eps=1e-8` 的 Adam 更新，三个更新量误差约 1.01～1.19×10⁻⁵，超过原门槛。整体更新误差相对 L2 约 **0.0968%**。这项严格失败保留。

另一个独立单真实 key 反例中，归一化 attention 输出恒等于 V，Q/K 梯度数学上应精确零；普通 tiled 反向产生约 2.4～2.9×10⁻⁹ 的残差。其 `gb @ V` 与逐元素乘积后求和的消减顺序不同，为后续有界处理提供了具体方向。该反例没有结构填充，也没有极小质量。本次未修改 attention 求导或优化器策略。

**必须限定暴露范围：**同一健康批次的实际 auto 路径在上述三个位置的梯度均为精确零，新旧 auto 都没有这三个更新超差。实际 auto 对 FP64 仍有一个 private KV values 字段超差，整体最大差约 1.76×10⁻⁵；其余比较字段满足原门槛。强制 tiled 对照还有同类状态超差，合计四个失败字段。不能把强制后端的残差当成已经证明主任务受到同样污染；auto 在其他输入上可能选择 tiled，仍需核验真实触发条件。

另一抽样来自健康采样中最大激活所在的 Exchange/S/capacity 候选，使用其最终 2,097,152 token checkpoint 的下一批次（不是最大激活发生时的原批次）。该样本对 FP64 的梯度和更新及状态均满足原容差，梯度相对 L2 误差约 4.04×10⁻⁶，更新约 3.07×10⁻⁵。两个抽样不足以认证全部候选。

## 现有记录支持什么

仅遍历当前 r07 scheduler、selected.json 明确引用的本周期尝试与接续祖先：1,171 个目录、**1,144,441 条已完成更新记录、3,041 份健康采样**，无解析错误或记录中的非有限值。该总数含重试/接续后的重复曝光，不是独立 token 数。

- 全批裁剪前梯度范数中位数约 1.196，p99 约 2.382，最大 96.677；健康采样中的最大单个真实参数梯度约 1.280。
- 失败任务本段 3,257 个已完成更新的范数为 1.046～2.370，中位数 1.208，没有持续爆炸的记录。
- 健康采样最大激活约 6,563.5。约 83.4% 的记录更新触发原范数 1 的裁剪；裁剪会限制大小，不能认证梯度方向正确。

每步的 loss/范数检查覆盖实际更新边界，健康采样覆盖部分时点、最多 128 个模块及 private-state 前 64 个叶子。它们没有保存所有中间运算。有限但错误的梯度可能通过这些检查；完整参数有限也不能证明一条长期轨迹代表预期数学。

因此没有证据要求整批作废，也没有依据宣布全部结果数值可信。当前曲线、checkpoint 和初步选参应保留；最终学习判断应等待修复版与原版本的证据迁移，以及剩余精度风险的有界审阅。

## 下一步建议，等待对齐

1. 先处理有独立数学恒等式的 tiled 单 key 消减残差，并检查实际 auto 会在什么真实输入下触发；保留真实零质量边的右导数与原数值门槛。
2. 在阶段 A 内增加有限的数值可信度抽查，覆盖初始化、训练中后段、极低活跃、极小质量和异常大激活：比较真实参数梯度、更新量、离散支持及状态，不只比较 loss 或 isfinite。
3. 把严格数值通过、精确状态加载、长期轨迹分叉与学习有效性分别记录。对有界舍入差异，额外评估其相对更新量、种子波动和模型收益差距的影响；原 Shannon/Exchange 超差继续保留，不能用效果检查替换或放宽严格检查。
4. 依据新身份完成受影响 A 证据的复核和 checkpoint 迁移，再决定保留/重做哪些选参。无需预先宣布全部重来。完整 A 与对照门禁满足后才进入 B。
