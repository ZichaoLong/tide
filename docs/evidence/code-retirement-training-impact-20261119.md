## 对训练的实际影响

已测固定路径可以完成训练和恢复，不等于所有执行方式等价。部分失败涉及梯度、
更新参数、输出支持及记忆时间，不能统一解释为无害舍入，也不能用自身恢复通过覆盖。

| 范围 | 已有证据 | 对训练的限制 |

| 默认CPU例子 | FP32 FC-K/d64、1线程、gather/rectangular；公开训练与恢复检查 | 小机制例子；没有任务质量或大模型资格 |

当前采用建议仍是FP32、匹配已测单卡预设、默认FFN执行；改变合批、重算、放置、精度或
记忆绑定时保持各自资格身份。CPU/NPU证据不覆盖CUDA硬件、完整编译训练或任务收敛质量。
完整配置解释见[训练建议](../execution-recommendations.md)，原阈值与来源见
[FFN报告](ffn-execution-devices-20261119.md)、[memory报告](memory-candidates-20261119.md)
及[精度契约](../precision.md)。

d768四项FFN原公式失败是输出比较，原输入/参数VJP在阈内；后续同NPU/FP64诊断没有追认。
中尺度NPU后续恢复使用显式新空梯度、seed2718参考，step4→5阈内，
不能称恢复原中断进程未保存的梯度/RNG。ModelConfig默认region batch1与共享9B实测size4不同。

## 已修复与仍有价值的代码

BF16 regional bias epilogue、BF16 Attention随梯度模式改变表示、inference-mode静态mask
缓存切回训练、测试线程数泄漏和诊断别名泄漏均已有修复。原失败继续保留；修复不消除其他数值差异。
旧取消矩阵、错误CLI和计时标签问题属于已归档工具事实，不是当前训练必须重跑的项目。

活跃src/tide的23个模块均有实际导入方及API/配置/检查用途。独立CLI没有静态导入方
不代表无用途；安装检查和有界诊断仍是复现入口。两个execution_suite编排的分别是资格与性能。
跟踪的src/tide、benchmarks、scripts、tests、configs合计1,867,538 B，生产源码222,695 B。
本轮没有找到足以判为无用的活跃生产实现或工具，故没有删减功能。

W/P/WP保留显式实验身份：同batch吞吐比0.991/0.854/0.813不构成加速，
但其显存收益仍有用途。全SSD、反向混合、窄KV和仅记忆共享也有参数/容量取舍，
不能因某条执行路径超差将整个实例删除。

## 实际清理范围

312份已终态实验的source对应40个提交，均可从已推送分支到达。逐文件计算Git blob内容身份，
122,974个归档文件全部与提交精确一致；另识别9,157个生成的Python字节码文件。
全部132,131个确认重复/生成文件已退休，释放13,940,666,368 B（约12.983 GiB）。
没有以文件名/大小相同替代内容核对，没有仅因Git clean删除ignored内容。

仅清理顶层artifacts/<run>/source内的上述文件；1,633个嵌套profiler/pytest缓存证据文件
保留原大小和mtime。运行根目录的原始结果、配置/命令、环境、状态、日志和dirty标记均保留。
362个剩余.pt的元数据与前轮保留清单一致，四份用户文档SHA不变；.f32、worktree、唯一ignored
源码、主math/.git、主开发环境、下游和公共环境未改动。

已退休source的原绝对路径不再是可运行安装，但身份仍可重建：

```sh
# 在新目录中重建，不将新运行写回原结果目录。
git archive RECORDED_SOURCE_COMMIT | tar -x -C NEW_SOURCE_DIRECTORY
```

每个run的固定提交、原终态及launch/status SHA见JSON。输入参数仍取原launch/结果记录，
按当时可用环境与资源重新运行；原测量身份不追认为新HEAD。

审计及删除分别由background.slice服务完成，均有限600秒、4 GiB采样RSS、CPU176–179；
实际约21.51/14.57秒，未使用NPU。冻结审计脚本身份和删除脚本的保护补充分别记录。
