原记录未保留逐时刻work/control，不能由Full净增1断言只改变了一个事件；差异位置和原因仍未知。




## 公式、实际工作和设备归因

令 `Rprep=N×B×L` 为prepare执行的候选矩形行，`Rfull` 为packing之后实际执行行，
`d/m/s/f` 分别为内容、KV内部、摘要、Full FFN宽，SSD头数 `h=d/32`。以下是
线性层multiply-add对数，未包含Attention、归一化、扫描、索引、适配器及调度，不是完整FLOPs。

| 路径 | 主要线性代价 |
|---|---|
| KV prepare | `Rprep×(2dm+ds)` |
| KV Full | `Rfull×(2dm+3df)` |
| SSD prepare | `Rprep×[d(2d+64+h)+2ds]` |
| SSD Full | `Rfull×(d²+3df)` |

KV prepare先拼接old/new的times、weight、keys、values、features五个字段，再按原始int64时间
形成短/长摘要和窗口可见性，最后压紧保留字段。NPU用按时间有序的prefix-count/cumsum/scatter
整理，CPU用稳定时间排序。窄m减少K/V载荷与投影，**不减少**固定摘要宽度、窗口控制及独立FFN。
旧状态、拼接bank、摘要临时量和整理结果可能同时存活，不能用最终缓存容量推算峰值。

SSD在Full选择前已完成input/gate/dt投影、四抽头卷积、`h×32×32`矩阵状态递推、
摘要和描述读取。持久状态小不代表只有Full行才花准备成本；全SSD把这部分扩展到普通节点。

```text
received = reception(messages)
descriptors, context, prepared_state = memory.prepare(received)  # 所有候选矩形行
control = regional_allocation(descriptors)
packed = pack(control > 0)                              # 节点×B×最大活跃query数
x = packed.data + memory_output(context, packed)
out = independent_ffn(x)                               # FFN包含x残差，执行padding矩形
publish(out); retain_private_state(prepared_state)
```

9B B8的X在KV Full中选中87,758行，执行517,000行（5.89倍）；KV384为87,055/535,040（6.15倍），
反向混合SSD为87,837/525,224（5.98倍）。全SSD的总选中/执行为180,029/600,480（3.34倍，含H）。
不同候选的活动不同，不能凭参数减少或语义活跃行断言同负载加速。
X的独立FFN占该次已计NodeLinear MAdds约54.13%；这是算术计数，不能当时间占比。

共享矩阵 `Wv=Wg+LvRv` 的两种实际基座执行方式为：

```text
# 全部possible owners使用同一基座
base = X.reshape(-1,in) @ Wg.T
# 跨区域owners混合：基座按节点重复收集
base = bmm(X.reshape(N,-1,in), W[groups].transpose(1,2))
out = base + bmm(bmm(Xflat, Rprivate.T), Lprivate.T)
```

每个数学NodeLinear的适配器需 `rows×rank×(in+out)` MAdds；逐头query适配器为
`rows×rank×[(m/32)d+m]`，不能把融合query当成单个总宽矩阵的一个适配器来少计。
中尺度共享、region_batch_size4的全模型NodeLinear基座实测120次BMM、0次MM；
其中共享记忆矩阵为48次BMM、0次MM，752个重复基座行全部来自这些共享记忆矩阵。
具体看到 `[32,1024,192]×[32,192,384]` 及两段rank8 BMM。
参数去重没有自动实现按区域较大GEMM复用，独立FFN也仍按节点执行。

## 采用建议

保持已有默认和X参照。若下游允许改变记忆函数，优先把FP32 KV128/KV256作为质量试验候选：
本轮B8吞吐和峰值优于X，近总参数KV128也保持优势，但尚未验证任务效果。
中尺度训练可从已测B16起步并为任务头/数据留余量；9B推理可选择表内同batch或预算内有限最佳，
不把它们当作最大容量。全SSD适合继续评估较小持久状态的推理负载；不能从decode收益推断零态训练收益。
记忆共享主要节省参数存储，独立FFN和重复基座BMM仍占成本；region1更慢且有支持差异，保留region4。
BF16、近参数FFN训练和新硬件组合保留各自未通过或未覆盖范围。可执行设置与边界见
[执行建议](../execution-recommendations.md)。
