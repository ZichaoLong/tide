FC-S 没有 K 的历史注意力对，表中的零不代表 S recurrence 没有工作。各阶段参数触及、
候选/消息容量、区域注意力正对、矩阵调用/行数及 logical materialization bytes 都保留在 JSON。
NodeLinear multiply-adds 仅覆盖记录到的矩阵行，排除 Attention/归一化等，不能叫完整 FLOPs。
复制/索引/拼接的逻辑输出字节也不是硬件总线流量或带宽。

Timed 的 sample-time domain 包含 4,160 个样本/tick（B8 下 520 个逻辑 tick），
但只有 1,024 个输入位置。它的初始触及均值约 10.88M/tick，累计约 44.21M/输入位置；
空间层数九层不替代时间展开的实际工作。此入口没有把窗口与 flush 分拆成独立正常计时。

多步优化会改变 Full、消息、候选及历史有效对；即使最终汇总一致，也不足以证明逐更新
同轨迹。跨设备的初始参数和输入哈希匹配及每项工作差保留在 `cross_device`；
FP32 CPU/NPU 也可能在后续更新出现细小工作差，BF16 初始差和构造变化更明显。

不同数学模型的必要工作量不同。Tide 还承担接收、准备、区域打分/分配、私有历史和图调度，
参数有效触及量不能直接预测这些成本。矩形 packing、重复矩阵调用及物化记录可定位额外
工作机会；本矩阵没有分阶段计时，不能将整个 Transformer 差距归给单一算子或 Python。
热点候选与侵入式阶段证据另见 [热点报告](roadmap-hotspots-20261118.md)，不与此处普通计时混算。

同构基线在不同任务/卡/时段也有明显时间差：例如 FP32 的 Multiscale Settle 与 Timed
A/C 构造相同，但 Timed 物理卡 10 的基线时间约为 Settle 物理卡 5 的两倍。当前记录
不足以区分频率、宿主调度或其他运行时原因；不可把跨任务差异解释为模型改变带来的加速。
CPU 固定顺序与有限五样本也有显著波动，A/B 或 C/D 构造相同时仍可得到不同中位数。
CPU 部分短基线的极差/中位数达 3.19；Timed NPU BF16 的部分 Transformer 样本达 1.05。
JSON 保留所有样本、极差/中位数及 host load，不宣称统计显著性，尤其不能从这些短基线
的细小次序差推断结构优势。本次未启动重测，若需要精确区分这些噪声敏感小差异需另设测量。

## 完成范围、失败与复现

CPU/NPU 的全部 28 个配置/精度子任务已终态完成，共 432 行、2,160 个计时样本，
本矩阵失败 observation 数为 0。数值资格、连续训练恢复、多设备放置、0.5B 以上规模
和其他组合各有独立证据；本矩阵的有限执行结果不改写任何已有 FP32/BF16 超差。

NPU 日志保留 32 padding 的 allocator 警告；Timed 另保留 internal-format/base-format 警告。
警告原文与日志 hash 在 JSON，未由这些警告推断主机 fallback 或算子失败。

复现环境见 [development](../development.md)，完整八组冻结命令和资源界限在 JSON 的
`runs[].launch`。必须使用新任务名/输出路径并重新按当前会话的设备准入权限排队，例如：

```sh
python scripts/launch.py --name new-representative-fc-k \
  --revision 778c65fb2961624bb416343eb3ad0f6f031deff7 \
  --npu-count 1 --threads 4 --affinity 80-83 --seconds 3600 --rss-gib 80 \
  -- python -m benchmarks.programme --suite representative --configs configs/fc-k.json \
  --device npu:0 --precision fp32 bf16 --threads 4 --batch 8 --length 128 \
  --warmup 2 --steps 5 --child-timeout 1200 --output-dir '{run}/results'
```

CPU 原命令去掉 configs 以遍历七配置，使用 device=cpu、32 线程、affinity 0–31、
7200 秒/128 GiB 进程树界限和 1800 秒 child timeout。独立匹配/统计验证入口为
`tests/test_benchmark_contract.py`；这些数学/统计检查与此处不同函数性能比较各自陈述。
