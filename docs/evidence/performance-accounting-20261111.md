## FC16当前模式

16节点、4串行区域×4节点、相邻区域全连接，B8/L128/d128/H2/FFN512；
summary/adapter/score/region hidden32。KV qry、Read+、cat/ind/context/cat、
regional_total/quad、temperature=.25、k2；完整任务5,092,788参数，core4,564,404。
拓扑全连接不等于所有候选都执行Full：训练两设备均16,384候选，实际Full为8,344/8,345。

Python调用C++/LibTorch、FP32、auto component-window/packed-v2、minimal返回。
CPU intra-op1；NPU mixed-c、host intra-op2、worker1，窗口推进仍在主机。
这是受控单线程CPU对照，**不是本机最佳多线程吞吐，也不是resident**。
每配置一次独立进程、预热后恢复初始参数再测量；共享主机争用未排除。

| 模式 | CPU秒 | CPU输入位置/秒 | NPU秒 | NPU输入位置/秒 |
| --- | ---: | ---: | ---: | ---: |
| 无梯度prompt→首token完整请求 | 2.738368 | 373.95 | 4.058731 | 252.30 |
| 无梯度全部位置head/loss | 2.818699 | 363.29 | 3.915932 | 261.50 |
| 含grad前向及全部位置loss，无反向 | 4.578968 | 223.63 | 7.448917 | 137.47 |
| 完整训练更新 | 12.283111 | 83.37 | 15.510679 | 66.02 |

每行吞吐=`1024/完整间隔秒数`。真实首token时延另为CPU2.736881秒/NPU4.054554秒，
是整个已加载B8请求的时延，不除以B或L；没有测后续decode生成吞吐。
prompt请求只做末位置head，不能将它与全部位置loss模式的差值全归为autograd开销。

## 直接公式与Transformer参照

以下均为同B/L/d/H/FFN和任务head的**完整训练更新**。直接FC公式与默认入口
使用相同模型参数/输入；Transformer为不同函数，参数量也不同。

| 实现 | 参数量 | CPU秒 / 输入位置每秒 | NPU秒 / 输入位置每秒 |
| --- | ---: | ---: | ---: |
| Tide默认FC16 | 5,092,788 | 12.283111 / 83.37 | 15.510679 / 66.02 |
| 直接FC公式 | 5,092,788 | 1.425050 / 718.57 | 0.712580 / 1437.03 |
| Transformer16 | 4,722,688 | 0.755807 / 1354.84 | 0.045640 / 22436.53 |
| Transformer4 | 1,576,960 | 0.246228 / 4158.75 | 0.018551 / 55200.34 |

Transformer4对照串行深度、Transformer16对照节点数量；两者都不包含Tide完整的
Read、区域证据/分配、消息和raw状态语义，不能用其差值直接认定框架冗余。
当前这组直接实现没有独立无梯度请求、含grad前向或TTFT测量；训练内前向阶段不能填补这些空格。

[FC公式](../../scripts/fc_tensor_baseline.py)保留核心数值代数、非零raw左态、共享及续接，
只声明输出/raw状态投影，不承担完整图记录和所有中间独立根。
它仍有B维主机循环、O(n²)分配区间枚举和数千autograd节点，**不是已证明的最优实现**。
小型独立投影资格不认证B8/L128完整尺度严格等价。

## 已量化的差额与尚未分清的原因

用同一次完整训练中的对应阶段计算`Tide默认−直接FC公式`，单位秒：

| 阶段 | CPU默认 / 公式 / 差额 | NPU默认 / 公式 / 差额 |
| --- | ---: | ---: |
| 核心前向 | 4.629191 / 0.512429 / +4.116763 | 7.213863 / 0.294949 / +6.918914 |
| 真实反向 | 7.538370 / 0.824657 / +6.713713 | 8.120481 / 0.351203 / +7.769278 |
| 完整间隔的其余差额 | +0.027585 | +0.109907 |
| 完整训练差额 | +10.858060 | +14.798099 |

默认耗时为公式的8.62倍/21.77倍。超过99%的粗阶段差额在核心前向和反向；
其余项是总差额减去前两项的余量，并非单个计时器。
这把问题定位到核心计算/状态/反向路径，**没有**分解出每个原因独立贡献多少。
直接公式也做区域分配，不能把全部差距称为分配或通用调度开销。

| 架构位置与代码 | 当前事实与可继续检查的接口 |
| --- | --- |
| [Read/Full查询](../../cpp/src/weighted_query_packed.cpp) | Read构造短/长记忆描述，Full生成选中节点输出。Full已用共享bank矩阵；Read历史投影/快照组装和块内伴随仍可检查 |
| [查询VJP](../../cpp/src/weighted_query_vjp.cpp) | `QueryVjp::apply`按使用行/根分组，调用私有`autograd::grad`并汇总。块接口与伴随规约可减少逐行装配，必须保留独立根、None/零和版本检查 |
| [区域VJP](../../cpp/src/weighted_region_vjp.cpp) | 区域控制/分配输出的梯度按使用mask/依赖组织；可检查批量边界及隐式VJP，未证明它占整个差额的大部分 |
| [snapshot bank](../../python/tidegraph/weighted/snapshot_bank.py)与[bank attention](../../python/tidegraph/weighted/bank_attention.py) | 数值存储已共享；独立快照伴随仍需区分。共享存储并不意味着可无条件合并梯度根 |
| [分层架构](../architecture.md)中的调度、状态与发布 | 合法批次、消息/pending、原始时间、checkpoint属于真实职责；当前实现这些职责的方式可以重设计，并非所有成本都不可消除 |

独立B2/L8/d128的阶段诊断中，query私有梯度CPU118.61/NPU258.59ms、
Read51.11/114.11ms、Full27.53/71.14ms、区域梯度23.14/57.15ms、发布1.74/1.67ms。
这是默认实现自身的calling-thread排他墙钟，包含提交/等待，不是硬件kernel时间，
也不是减去直接公式后的开销；不能外推为B8/L128的各项占比。

另一B2/L8/d32图诊断：PyTorch默认9,920、native10,298、直接FC公式CPU5,095/NPU4,061、
Transformer4 CPU183/NPU143个图节点。默认计数包括已注册私有图；不能只看外层约1,100个节点。
图数有助于识别组织成本，不与耗时成正比，各诊断的d和计数宇宙也不同。
