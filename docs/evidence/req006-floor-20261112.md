# REQ-006：常量表示、clamp 反向与初态配对（2026-11-12）

本轮将[四代表诊断](req006-diagnostics-20261112.md)中的浮点 clamp 反向热点缩小到
可独立复现的算子见证：**原 Python float 的 Scalar 调用出现两个 AICPU kernel；
显式舍入为 FP32 后的 Scalar 和同 dtype/device Tensor 调用均未出现 AICPU。**
两种常量表示在阈值处具有不同的实际 VJP，不能直接宣称等价替换或厂商数学错误。
另外，新增跨进程初态复用已在小型 CPU 用例通过，解决后续 measure/profile/census 的材料配对。

[复核附件](req006-floor-20261112.json)保留10个算子 action、3个配对 action 的实际结果、
原始文件 hash、完整13点边界材料、kernel 名称/类型/耗时及失败作业身份。
本轮不修改生产函数或下游代码，不新增整模型提速、基座续接或下游验收结论。

各运行均为干净固定源码。入口为[diagnose_scalar_floor.py](../../scripts/diagnose_scalar_floor.py)，
独立锚点是按输入 dtype 表示阈值的分段公式。对本次有限输入：

```text
b = round_to_float32(log(float32.tiny))
y = where(x >= b, x, b)
bar_x = where(x >= b, bar_y, 0)    # 相等点选择输入分支；阈值不是梯度根
```

原请求 Python float 为 `-87.3365447505531`，FP32 表示为 `-87.3365478515625`。
后者比原请求更小。因此 `x` 恰等于 FP32 表示值时，并不等于原 Python float；
对原阈值比较得到零梯度，与上述 dtype 阈值公式的相等点梯度是不同身份。
本探针只判定是否符合其**明确声明的 dtype 阈值公式**，不据此裁定下游应采用哪种边界 VJP，
也未验证厂商内部全部精度/提升规则。前向值一致不能代替这个判断。

13点包括阈值相邻可表示数、相等点、两侧偏移、signed zero、normal tiny与次正规数；
cotangent 含正、负、零。原 Scalar 恰有1点 input VJP 与锚点不同：
`x=-87.3365478515625, bar_y=-3` 时，实际为 `0`，锚点为 `-3`。
Tensor及显式 dtype Scalar 的13点值、VJP、signed zero均一致。

## 实际 NPU 成本与设备路径

形状统一为 `[4,16,256,256]`，4,194,304元素，FP32；将13点材料循环填充到实际形状。
前向及 input VJP 每步重新构图；每进程1次warmup、1次measure或profile，二者独立进程。
输入与cotangent共32MiB。常量构造/上传、输入构造/上传、检查/读回/hash、预热和trace导出
不在步骤计时内；前向、autograd及终端设备同步在内。没有optimizer、模型吞吐或TTFT含义。

运行时为aarch64、Python3.12.13、Torch2.12.0+cpu
（git `7661cd9c6b841b62b7f411aa52ec51f05457263b`）、TorchNPU2.12.0.post3、
CANN9.2.0、Ascend910_9392、CXX11 ABI=true、matmul HF32=false。
ATen intra-op2/inter-op1；OMP/MKL/OpenBLAS环境均1；未设置launch blocking。

仍记录 `strict_formula_passed=false`、`failure_kind=finite_numeric`、`state=failed`及退出1。
全形状前向一致，梯度有322,639个不同坐标，恰对应重复模式中的阈值点。
另外6个通过action只认证所选择variant；其小边界记录包含另一variant的失败，不将它抹去。

早期失败的两个Scalar action尚未物化全形状材料。

这支持“常量表示会改变实际分派”的具体判断，不支持“Scalar必慢、Tensor必快”。
AICPU是设备任务类型，不是host fallback；本轮未观察到具名host fallback事件。
设备累计时间/并集不是整模型关键路径分摊，不能把352次单算子差额相加预报HB88收益。

## 跨进程初态配对资格

[req006_initial.py](../../scripts/req006_initial.py)保存模型/缓冲、完整AdamW槽及CPU/设备RNG；
`--initial-state-out`在prime之后发布，`--initial-state-in`核对配置、输入、进度、prime来源、
固定下游源码及关键数值runtime，再恢复并核对完整hash，跳过prime。
action/mode/物理卡号可不同；设备类型/型号、实际线程及精度身份受到约束。
使用`weights_only=True`；同目录staging、fsync及hardlink原子不覆盖发布。

固定f681的40项定向检查通过：初态23、既有诊断11、LH检查6。
初态检查覆盖含随机输入/Dropout的精确下一次AdamW更新、身份/内容拒绝、字节预算、
既存文件/符号链接和失败/并发发布不覆盖；不将40项都称为初态检查。

三进程实跑为固定下游的**小型SmallTransformer**：width4、一层、head1、FFN8，
20,660参数；CPU FP32、intra-op1/inter-op1；global batch2、microbatch1、L3，进度29。
input seed17、model seed11，prime1、warmup1、观察更新1。measure实际prime1，profile/census

## 复现与采用边界

环境/冻结源码按[development](../development.md)及[持久作业契约](../execution-flows.md#7-提交资源与交接)。
以下是已完成设备准入后的workload命令，每action独立新目录/进程，默认1次warmup/1次观察；
单action120s、64GiB预算足够本次范围。空闲卡按现行入口准入；共享卡仍需当前会话授权，
不复用本报告的过期共享policy，也不依赖旧venv或raw目录。

在固定7d5运行原常量见证；该命令预期保留退出1，另以profile新进程收集trace：

```sh
python scripts/diagnose_scalar_floor.py --device npu:0 --dtype float32 \
  --bound log-tiny --bound-representation requested --variant scalar \
  --observe-finite-mismatch --shape 4,16,256,256 --mode backward \
  --action measure --threads 2 --output-dir artifacts/floor-requested-measure-new
```

dtype候选在固定3f99运行同一命令形状，改为`--bound-representation dtype`，
不加`--observe-finite-mismatch`，分别选择`--variant scalar|tensor`及`--action measure|profile`。
原a95见证没有这两个新增开关，其Scalar严格检查会在计时前失败。

要复现f681三进程配对，从后继归档取同字节fixture（源代码仍固定f681），
再运行以下三个独立action。下游路径须包含上表固定Git对象，脚本仅从Git提取源码：

```sh
git show 3f99eb22e520f87bd5cbe378b0b0c6a9f774e8f9:tests/fixtures/req006-tiny-transformer.json \
  > artifacts/req006-tiny-f681.json
REQ006_ARGS=(--config artifacts/req006-tiny-f681.json \
  --downstream-repo /path/to/tide-learning-lab --device cpu --threads 1 \
  --progress-tokens 29 --prime-updates 1 --max-trace-bytes 16777216)
python scripts/diagnose_req006.py "${REQ006_ARGS[@]}" --action measure \
  --initial-state-out artifacts/req006-initial-new.pt --output-dir artifacts/req006-measure-new
for action in profile census; do
  python scripts/diagnose_req006.py "${REQ006_ARGS[@]}" --action "$action" \
    --initial-state-in artifacts/req006-initial-new.pt --output-dir "artifacts/req006-$action-new"
done
```

本证据支持下一候选在固定`direct_semantic_ops.positive_exp`调用点明确常量及边界VJP身份，
按同一初态、完整更新范围验证值/梯度/实际kernel和成本；**不支持全局monkeypatch clamp**。
如需保持原Python float比较的VJP，应先使候选保持该边界，不能把dtype舍入当成无条件优化。
本次未认证阈值根梯度、double backward、NPU其他dtype、NaN/Inf或完整模型替换；
相关剩余实施与选择继续由[ROADMAP](../ROADMAP.md)管理。
