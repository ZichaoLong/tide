# r07 反传异常调查（2026-11-20）

结论：本次失败由 **Reception 的结构填充槽未被掩蔽** 引起。原模型中不存在的两条边被当作真实零质量边计算右导数，产生FP32无穷大，再经布线处的零乘法变成NaN，最终由allocation的保护检查报告。调查已用原失败载荷、逐算子反传跟踪、独立FP64公式及完整模型单步测试闭合证据链。

本次仅新增隔离的诊断脚本、诊断产物和审阅文档。生产实现、冻结输入、环境及原失败记录均未修改，训练服务保持停止，B关闭。机器可读依据为[调查证据](evidence/pilot-r3-r07-vjp-investigation.json)，脚本和原始诊断产物位于 `.local/pilot-r3/diagnostic-r07-vjp-r01/`。

## 失败链

任务为 `multiscale_settle-d64-k-singleton7-121b8d2af3-a3-2026112001-r2`，CPU FP32、batch=2、4线程、名义lr=0.001。已完成7353步/1,882,368 token，在下一次反传失败。保存的全部模型、优化器和private-state张量有限；原失败批次前向loss=5.369584560394287，logits全部有限。

1. 区域8的节点12、13分别有5条、7条真实入边。节点12为矩形布局补齐的slot 5、6（零基索引）没有真实边。冻结配置 `reception_mask_padding=False`，故 `_reception_mask` 返回None。
2. `Reception.forward` 把这些零mass槽传入加权attention。零mass边有合法右导数这一契约适用于真实存在的边；此时它错误地覆盖了填充槽。
3. 第一处非有限值来自 `_TiledAttentionBackward` 的mass梯度。输入Q/K/V、mass、上游梯度均有限；Q/K/V梯度仍有限，只有两个填充mass位置产生−Inf。
4. 用保存的Q/K/V、mass和上游梯度做独立FP64归一化加权和，再由标准autograd求导，两处导数均约 **−4.160312849×10³⁸**，为FP32最大值3.402823466×10³⁸的1.222606倍。这不是独立指数溢出后本可恢复的有限乘积，而是假设空槽是真实边时的最终不可表示导数。
5. 第一处NaN实际位于冻结 `foundation/src/tide/model.py:197`：`strengths[ids] * valid` 的反传计算了 `−Inf × 0`。真实布线梯度被污染后，`allocation.py:462` 的 `_finite_vjp` 收到NaN并报错。因此报错位置不是最初产生非有限值的位置。

独立最小反例只需要一条真实边和一个由 `strength*0` 构造的填充槽：前向恒为1，原路径给strength返回NaN；使用拓扑成员掩码后，前向仍为1，梯度精确为0。

## 建议的修复方式

优先把静态拓扑成员掩码作为Reception的正确性约束：不存在的边必须始终被排除。现有 `reception_mask_padding=True` 已提供这一能力，本次测试验证了直接启用它的修复方向；在正式实现时，应确保所有普通、区域批处理、重计算及放置路径一致传递该掩码，避免以可关闭的性能选项承载必要语义。

掩码须来自拓扑成员关系，不能写成 `mass > 0`。真实存在但当前mass为0的边仍须保留原右导数。无需降低原有限值门槛、裁掉大梯度、给mass加epsilon或改变Shannon公式；这些措施不修复空槽和真实边的混淆。

可另外在普通tiled attention的VJP出口增加有限值诊断，使未来真实范围失败直接报告原算子及梯度种类；这只改善定位，不应过滤、截断或伪造梯度。

落实前还需对实际CPU/NPU后端、上述布局分支及checkpoint接续做针对性资格测试，记录auto后端变化及可转移证据范围。有效模型结构key在本次选项测试中未变，但完整任务/执行契约仍有变化，不能据此宣称旧轨迹完全相同或绕过冻结身份。

真正恢复时应使用审计后的健康checkpoint，并绑定新的配置/源码身份；`failure.pt` 明确为诊断专用、不可恢复，缺少完整stream/RNG契约。原任务最近健康checkpoint为1,861,888 token，所有旧失败及曝光成本继续保留。两项收尾SIGKILL任务的恢复资格是另一个待办，本次未将其判为可恢复。

本轮调查已完成；尚未实施修复，也未重新拉起A/B队列。原Shannon恢复超差和全部数值门槛保持。
