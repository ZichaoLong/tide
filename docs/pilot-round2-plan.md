# 第二轮：修复、并发成本与真实接续

用户于 2026-11-19 批准执行。正式表为 [72 项任务](../configs/pilot-round2/plan.json)，58 NPU、14 CPU，最长 5,400 秒，预计约 60–90 分钟；提前 300 秒停止派发，预留终态清理。一次性实现、受影响检查与 NPU 接入另记。轮末汇报对齐，第三轮与后续长队列不自动启动。

本轮保持第一轮数学、WikiText103 文章级留出、BPE8192 和 FP32。外部基座及共享环境保持只读；采用第一轮固定 commit `bef26abb2458cfff003c84f376f93bc18a0b4106` 的项目私有副本，加 [Shannon cap 补丁](../patches/pilot-round2-shannon-cap.patch)。源身份以原 commit、补丁及完整内容 SHA 共同定义，不把私有补丁称为上游已修复。

原 NPU 失败已经捕获：初始验证 batch 0、region 8、D 节点 48–55，索引 `[1,49]` 的一行总量残差约 0.0472。修复后的原输入通过 CPU/NPU 的独立解、边界/KKT 和 VJP 检查，原容差未变。[修复证据](evidence/pilot-r2-shannon-repair.json)保留原失败。整模训练和连续恢复仍要通过接入及正式任务观察。

整合预检 v2 的四项执行已完成，Transformer 父/子与 Shannon 子段的连续 8 步恢复在原容差内。Shannon 父段在全局第 13/14 步的私有 `K.values` 超差；保存/恢复摘要、输入、RNG、游标、结构和整数一致，首个浮点差异出现在第 10 步 loss（1 ULP）及裁剪后梯度，因果探针通过，尚未定位具体后端算子。[分歧审阅](evidence/pilot-r2-preflight-triage.json)保留原失败与阈值。正式表中的两个 Shannon 任务仅作限定时长、从头开始的学习观察，不参加自动学习率选择，也不据此宣称严格恢复合格；非有限、求解器及执行错误仍按失败终止。

| 自动选择并接续 | 6 | 每模型选完整种子组均值最佳的学习率，两个种子分别从父 checkpoint 继续 |

校准任务使用 `lr=0`，仍执行前向、反向、裁剪与 AdamW，以固定权重减少学习进度造成的工作量差异。这些任务没有模型学习结论。Shannon 训练与学习率初筛/接续使用正学习率，另行统计。batch 与长度、线程与 NUMA、参数量不同的任务不能简单按吞吐排名架构。

NPU 配对固定同一物理卡、相同 CPU mask、模型、精度、数据流和配方，CPU 配对固定相同 mask 与线程数。共同训练步前缀还核对输入/RNG 指纹，并从逐步时间记录检查实际训练重叠。混合阶段需要等待协作队列准入，未达到目标并发或匹配条件时报告缺口；不将 worker 生命周期重叠等同于训练并发，也不宣称跨项目 CPU 独占。本轮不进行同卡多任务。

初筛模型为 FC-K d128、Exchange-X d64、Transformer d256×6。每个学习率 `1e-4 / 3e-4 / 1e-3` 在种子 `20261119 / 20261120` 上各训练 257 更新（B8/L64，131,584 token），用固定 4,096-token 留出探针选择同一模型内的最低平均 NLL。只接受执行完成、恢复在原容差内、两个种子均达到准确曝光的组；失败候选不作为 0 分或缺省通过。平局取较小学习率。这是有限候选的自动筛选演示，不是架构质量排名或充分调参结论。

晋级任务从对应种子的父 checkpoint 追加 768 更新，预期全局步数 `257→1025`、总曝光 524,800 token。学习率按全局步数继续，优化器、数据游标、RNG 和私有状态一并恢复；仅新增更新预算允许改变。学习任务每 128 更新保存，父/子末尾分别再做新进程连续 8 更新比较。checkpoint v2 绑定模型/优化器/数据流合同、实际实验源码与基座身份；第一轮 v1 checkpoint 不被静默迁移。

新增逐步输入与 RNG 指纹进入测量边界，保存及 JSON 写入单列。因此不能把本轮与第一轮的吞吐差直接解读为纯实现变化。浮点继续使用 `atol=1e-5, rtol=1e-4`；输入、RNG、流游标、结构和整数检查严格比较，有限超差与执行失败分开保存。

正式运行使用全部协作队列允许的空闲 NPU，最大 16 个待执行 NPU 请求、4 个 CPU worker；配对阶段按计划固定候选卡并使用阶段屏障。当前候选卡快照为 `0,2,4,5,7,8,10,11,14`，实际准入仍需队列两次检查及锁。CPU 总可用亲和性 320 核。

内存采用整轮 192 GiB RSS 软件看守：每秒采样整个进程树，准入保留 16 GiB，并保持系统至少 128 GiB `MemAvailable`。声明估计乘 1.25 余量，普通任务 4 GiB、大 batch/Timed 任务 8 GiB。观测失败或超限停止准入并清理；实际采样间隔及峰值入日志。RSS 可能重复计算共享页，采样间隔内也可能超限；它不是内核硬上限，systemd 请求值不冒充实际控制器约束。

输出上限 512 GiB，同时受账号实际硬配额、软限宽限、文件系统空间与 16 GiB 留量约束。按多步恢复与大状态将单任务写入预留提高至 4–8 GiB，保留所有最终 checkpoint；成功的比较临时载荷清理，失败载荷保留。
