# TIDE 语义锚点与仓库分工

本页是上游语义的短锚点，版本为 **tide-core-3**。它确定教材落点、共同边界和下游引用方式，不复制全部定义。读者从 [总览](README.md) 选择学习入口。

本版本将 SettleGraph 聚合扩为带来源标签的序列接口；旧裸值聚合通过忽略标签保留。语义版本不代表任何下游实现已经通过对应验证。

在明确编码与投影下，SettleGraph 核心属于 TimedDAG 的受限类；TimedDAG 是 PositiveDelayGraph 的无环、有限输入特例。入门顺序不要求从最一般对象开始。

## 共同语义边界

1. 节点、消息边、端口和区域集合有限；固定消息边的时延是严格正整数。
2. 图结构在一次规格内固定。输入位置、统一逻辑时间与实际执行次序分开。
3. 每节点每逻辑时间至多处理一个完整纤维；每条出边、输出端口每次完整作用至多给出一个值。
4. 聚合输入保留来源：TimedDAG 与 Graph 使用端口或消息边，SettleGraph 使用入口、父边或终端节点标签；具体函数可以忽略这些坐标。
5. 候选来自非空输入纤维，激活集合是候选的子集。非候选节点不自主激活或发消息。
6. 每份节点状态由唯一节点持有，每份选择历史由唯一区域持有。固定参数可共享，隐式共同读写可变状态不在核心内。
7. 区域选择返回激活集合、每个候选的局部控制量和下一选择历史。历史更新可使用本次选择，不能读取本次完整输出。
8. 状态采用确定本次计算快照；Next 根据旧状态、快照、逻辑时间、本地输入、激活与否及本节点控制量，确定下一持久状态。
9. Full 读取快照、逻辑时间、本地内容与本节点控制量，产生消息／输出值；它不回写持久状态，Next 也不能通过重算 Full 绕过这一限制。
10. 非候选节点与空候选区域的保存状态坐标保持。时间衰减的有效状态可由“保存值＋时间戳”解码，不能用访问序号替代统一逻辑时间。
11. 局部函数为确定的全函数。控制量中的概率数值不自动引入随机选择。

完整逻辑时间切面的 continuation 保存绝对时间、下一持久节点状态、选择历史和所有跨界消息。本次控制量与计算快照是已完成事件的局部坐标，不必作为额外待执行状态保存。执行途中暂停属于更细的恢复契约。

## 前向、训练与时间批

局部控制量允许前向使用选择权重，包括 SOFTP。HARD 与 HST 可以具有相同前向值，但 HST 的替代反向规则必须另外声明；前向相同不自动证明梯度相同。

节点级时间批需要固定作用成本标记与精确联合契约。当前分块教材分别定义逐坐标 Full 批、从左边界状态出发的因果状态块、状态—Full 联合节点块和区域控制—状态块。最大前沿递归相对于这组契约在线构造当前合法块，并分别计量自适应阶段、状态批与 Full 批。严格分层类在具有相应精确见证时得到与 chunk 长度无关的外层块数。

核心局部语义仍要求 Next 在本次 Full 以前确定。若 Full 结果决定下一私有状态或共同选择，就必须改变规范事件边并重新证明 continuation；这类扩展不属于当前核心教材。

零时延边不进入当前设计与研究候选。证明中解释正时延前提的重要性不表示计划实现零时延。

## 下游如何引用

上游仓库是 [ObsidianVault](https://github.com/ZichaoLong/ObsidianVault)，语义路径是本目录。下游应记录：

| 字段 | 内容 |
|---|---|
| upstream repository | 上游仓库地址 |
| upstream revision | 采用的不可变提交，不只写随分支变化的链接 |
| semantic version | 本次为 tide-core-3 |
| adopted family | Graph、TimedDAG、SettleGraph 及附加限制 |
| local choices | 具体函数、尺寸、初始化、聚合、发送和状态规则 |
| local extensions | 超出上游函数类型或依赖边界的变化 |

如需离线阅读，可保存本锚点的固定版本副本，标记来源与提交，从上游单向更新。不能在两个仓库独立编辑“唯一语义定义”。下游可保留自包含实验说明，但须区分继承定义、具体实例与本地扩展。

本版本的 SettleGraph 定义参考了 fractal-latcarf 的 experiment-semantics-and-naming.md，并以本文所链接教材的符号重新表述。具体实验构型与上游提交的对应由下游记录。HARD/HST/SOFTP 前向可经控制量接口表达，仅依赖选择的历史写回可经 SelStep 或 Next 表达。自定义设置若读取 Full 结果后回写、采用共享可变状态或改变逻辑时间，必须另行登记，不能凭同名字段认定符合本版本。

上游 SettleGraph 教材把逻辑日程作为明确数据。下游函数忽略逻辑时间时，可选合法编码证明前向对应；启用时间衰减后，双方必须采用同一逻辑日程与解码规则，不能以 Token 计数直接替换时间差。

## 职责分工

| 内容 | 上游 | 实验平台 |
|---|---|---|
| 抽象接口与语义 | 定义与教材 | 选择实例并声明偏离 |
| 一般等价性 | 比较对象、定理及前提 | 实现检查、容差、随机性与证据 |
| 模块与构型 | 通用限制，候选动机放备忘 | 具体公式、拓扑生成、参数与状态尺寸 |
| 模型接入与生长 | 一般组合／投影保持条件 | 位置、权重装载、初始化与训练 |
| 性能与学习 | 问题、代数条件、复杂度边界 | kernel、吞吐、显存、质量与对照 |

上游可保留服务于教材的最小 reference 与手算实例，不承担实验平台的维护职责。
