## 1. 已认可的研究定位与基本路线

实验分支与工作目录均为`tide-learning-lab`。
核心问题：具有私有状态、区域局部决策与稀疏消息传播的core-5，能否学会任务，
并在保留任务质量的同时减少实际计算与通信。

按[下游契约](https://github.com/ZichaoLong/tide/blob/85d161d5c9148eac2b164f89a0ba4204b4331898/docs/downstream-contract.md)分工：基座拥有数学对象、公共模块、执行、反向、
optimizer机制和图续接；实验拥有数据、任务头、loss、配方、搜索、效果与应用checkpoint。
公共能力缺口通过需求、交付、下游验收、显式更新锁处理，不复制调度核心或依赖内部benchmark。

区分模型的信息/决策局部化、执行的多设备分布和学习规则的局部化。
节点依自身输入/状态，区域选择使用本区域完整候选；区域Attention仍需区域内协作。
初期允许端到端loss与统一optimizer。局部loss、异步更新等需另定义和验证，不能从前向局部性推导。

稀疏分别记录图连接、candidate/Upd/Read、Full、消息与实际计算/通信。
所有已收到输入的候选保留状态更新。FC减少Full仍可能保留全部下游准备；
HB邻域可减少下游候选，但教材HB实例仍保证各区域有活动。
发送强度总量、正支持数、参数量和实际算子工作是不同量；k通常不直接限制正支持数。

| 阶段 | 研究范围 | 推进依据 |
| --- | --- | --- |
| 0 接入 | 极小模型的embedding/读出/loss/optimizer/数据状态与完整恢复 | 因果性、完整记录、独立根/共享梯度、streaming/prefill、新进程恢复 |
| 1 可学习基线 | KV与小FC/SettleGraph，持续稠密发送；延迟复制/关联检索 | 拟合及独立样本泛化，超过无记忆/简单基线，图内计算实际被使用 |
| 2 稀疏多区域 | 小HB；稠密、固定稀疏、可学习稀疏 | 任务质量与candidate/Full/消息折衷，饥饿、塌缩、梯度覆盖 |
| 3 局部专题 | 各记忆/描述/评分/发送/位置/共享及少量交互 | 有益、无益、失败或未区分；不做全部组合 |
| 4 时间与反馈 | 非对齐TimedDAG、一般端口、真实反馈PDG | 输出切面、pending、跨窗信用与结构作用；同模型嵌入和新模型分列 |
| 5 真实序列 | 小型LM后再扩数据/长度/参数；FC/HB及少量LH启发连接 | 验证质量、生成、长程记忆、质量—成本曲线与关键多种子确认 |
| 6 系统扩展 | 已学会任务的模型迁native/resident/多设备 | 同模型实际工作、通信、容量、完整训练/推理与恢复 |

这是可调整的研究次序，不是必须逐格全通过的流水线。第2阶段开始检验最终目标；
后续专题围绕已有问题展开。真实反馈PDG显式给定读出切面/计算时限，不依赖队列最终清空。

| 局部专题 | 已认可的比较方向 |
| --- | --- |
| 记忆 | KV、affine、delta、GDN、SSD及少量异构区域；检索、压缩、长期反馈 |
| 描述/读取 | sum/qry、Read 0/-/+；当前输入、旧记忆、新写入的作用 |
| 评分/证据 | cat/match、ind/att、content/content_stats、cat/grouped；分工与准备成本 |
| 发送 | total/threshold/constrained、quad/ent/bern、Attention/比例/硬函数；幅度、支持与学习 |
| 时间 | 窗口、NoPE/RoPE、短卷积与真实空档；原始逻辑时间不改为活动计数 |
| 来源/共享 | 区域共享、节点私有、来源适配、共享基座/私有适配器；专门化与参数效率 |

所选任务需能区分候选：单位接收的等值分支、k=1的总量退化等不提供控制头效果证据。
优先在同一分配框架内比较稠密Shannon与正温quad，必要时固定alpha>1的ent。
硬选择的score排序无梯度，没有隐含旧HST；regional_total_zero可发送小数，不能当硬Top-k。
退火、教师、成本目标和辅助监督各有独立配方及额外成本。软硬比较各自从初态运行，
中途换函数保留旧缓存另立部署定义。

首轮候选任务为延迟关联检索（含干扰、距离、时间空档）和条件序列任务（检查任务相关分工）。
小FC/HB、十几个至几十个节点、小宽度，真实参数由planning报告；先单种子排错，
关键结论再至少三个种子确认。里程碑是任务学会、记忆有用、稀疏折衷可解释、训练/推理可恢复。
这不是已选定的作业矩阵，也未指定最终训练步数或资源预算。

LM后继固定tokenizer/数据划分/token预算，对照从头训练的小稠密Transformer，必要时普通MoE。
公共Qwen吞吐是部署背景；同总参数、同活跃计算、同质量的比较分别解释。

每阶段同时记录任务质量、模块更新/有效梯度、路由变化、写入到读取距离、真实工作、
prefill/生成成本、逐卡内存和独立检查。明确BPTT/截断、detach、参数更新后的状态策略。
基座已有小型资格不认证新任务；CANN9.2综合根严格失败保持，见[基座交接](https://github.com/ZichaoLong/tide/blob/85d161d5c9148eac2b164f89a0ba4204b4331898/docs/STATUS.md)。

工程起点采用[配置任务示例](https://github.com/ZichaoLong/tide/blob/85d161d5c9148eac2b164f89a0ba4204b4331898/examples/consumer_core5/configured/README.md)、公共task.plugin及
plan/check/run/job/results。CPU微型独立参考、NPU实际训练；native接共同代表，其他客户端独立迁移。
公共CANN9.2基线加下游自己的私有增量和固定wheel；不共用当前检出的editable venv。
配置区分模型/任务/配方/执行/站点，保存数据、RNG、scheduler和应用恢复状态。

## 2. 本轮新增诉求

用户通过数学文档牵引架构/语义，通过实验推进理解风险并分配有限资源。
需要同时支持两条路线：从局部化/稀疏化目标构造可验证的core-5模型；
从已有可靠模型通过继续训练、局部替换、residual旁路等逐步靠近目标，也保留从零训练。

## 3. 建议的组织单位：研究问题、比较与证据

人类优先看到“哪些判断已经有依据、下一步能排除什么”，单次run是其中的证据。
区分数学已证明、实现符合定义、模型能够学习、质量/成本收益、跨环境迁移五类判断；
数学命题记录适用前提，训练结果不承担证明数学定理的职责。

一个研究问题关联一组候选、对照及共同评估，运行后形成限定范围的结论。
结果正面/负面/未区分/运行无效各有用途。环境或数值失败不自动反证架构，
任务失败也不自动否定局部公式。筛选/确认实验角色与strict/explore数值策略是独立维度。

保留两条独立关系：
- 权重/状态谱系：精确resume、权重初始化、蒸馏、残差扩展、块替换、从零训练。
- 结论关系：直接支持、反证、冲突、条件迁移启示、待验证。它不是checkpoint继承关系。

每条结构转换说明改变的部件、保留的能力、目标相关性和新增风险。
每个模型列局部性、状态私有性、图邻域、候选/Full/消息实际稀疏及仍保留的全局机制。
局部化程度与证据成熟度并列，不合并为一个完成百分比或任意加权总分。

## 4. 从可靠模型逐步靠近的对照

可靠基线先在选定数据、精度、实现和设备上校准；固定checkpoint/tokenizer与已有训练背景。
路线可以是原模型→中性旁路→非中性且参与学习的旁路→替换一个块→多个块/局部区域。
它与小型纯core-5路线通过共同任务/评估连接；没有保证所有模型都适合这种替换。

对同一研究问题优先保留原模型同预算继续训练、Tide改造，以及必要的简单适配器/稠密分支对照。
保持数据暴露/更新预算，另报告实际计算；不能同时匹配的参数、预训练成本等明确列出。
冻结/解冻、训练参数量、loss/教师、数据与初始化全部记录，冻结基座仍计前向成本。

中性残差初态必须检查输出及状态投影、位置/KV/续接，单次logits相同不足以声明函数保持。
alpha=0且固定会阻断该支路任务梯度；可训练门或零输出投影各有渐进学习过程，需要实际观察。
训练后比较分支是否贡献、是否只靠原骨干、替换后能否恢复质量及是否减少工作。
关闭分支的干预只能说明已训练模型依赖它；与重新训练替代方案比较才能评价设计取舍。

模型改变后的质量比较和同模型独立数值检查分别记录。旧checkpoint装载为初始化不叫精确resume。
预训练骨干旁路成功只支持该接入与适配条件，不能认证从零训练、完整替换、HB或反馈PDG。

## 5. 有依据的迁移启示

每条启示最少给出：
1. 支撑结论的实际实验、重复/种子、对照及结果幅度；反证/未成功尝试同时可见。
2. 已测试的任务/规模/图/局部组合/初始化/反向/设备范围。
3. 想迁往哪里，哪些机制与条件不变，哪些维度改变。
4. 支持迁移的数学条件或相近实测，尚未覆盖的耦合与可能失败原因。
5. 最便宜的桥接检查，以及它怎样改变继续投入的决定。

建议用“原范围直接支持”“可优先尝试（列条件）”“有冲突”“无依据”呈现，
不自动生成成功概率。A+B、B+C各自成功不推出A+B+C成功；无相互作用假设也需要依据。
同一训练轨迹的多个checkpoint不是多份独立重复。理论条件可以支持精确求值迁移，
不能顺带转成学习效果或硬件加速保证。

例如KV/qry的检索收益可支持在相近HB中优先尝试；HB改变了候选接收历史与梯度覆盖，
不能直接继承效果结论。CPU下同模型质量证据可用于选配置，NPU的数值/速度仍需相应检查。
以上仅为解释示例，没有新增实测结果。

## 6. 面向发起人的四个视图

| 视图 | 默认回答的问题 | 细节入口 |
| --- | --- | --- |
| 目标与证据概览 | 局部化/稀疏/可学习/效率各进到哪里，最近改变了什么判断 | 数学条目、研究问题、正负证据与未测范围 |
| 模型演进图 | 从哪个基线经何种改变到当前模型，仍保留哪些原模型能力 | 权重/状态谱系、配置差异、旁路/替换占比 |
| 对照与迁移页 | 对同一问题，谁优于谁、付出何种成本、可迁往哪里 | 训练曲线、质量—成本图、实际工作及迁移卡 |
| 下一批资源页 | 哪项不确定性最值得消除，少量/更多资源分别能回答什么 | 预算、先决证据、成功/失败后的决定与停止条件 |

首屏以少数研究问题和结论为主，运行日志向下展开。虚线表示未实测迁移，实线关联实际比较；
支持与反证同时展示，不能仅靠颜色表达。可按任务、模型家族、局部语义、图、规模与平台筛选。
质量—成本曲线只在可比较口径内生成；教师/适配/预训练背景、返回与设备争用明确列出。
相同模型在不同硬件上的设备时不直接合成一条架构优劣排序。

每组实验结论控制在一页：问题、候选/对照及变更、主要图/数值、证据边界、迁移启示、下一决定。
摘要与详细HTML/CSV从同一组记录生成，人类解释有作者/版本/来源，自动归档不自动确认科学结论。

## 7. 资源决策与有界推进

每次申请说明：当前未知、已有依据、最小决定性实验、资源及时间范围、将交付的证据。
给最小/扩展预算两档；用短pilot校准速度与内存，实测与估计分列。
设备型号/数量×时长、主存/逐卡显存/磁盘/数据成本分别报告，异构卡时不直接相加当等价算力。
共同基线的成本可复用，但数据/实现/环境变化需要重新判断其可比性。

优先次序由目标相关性、能否区分解释、能否解锁后续和成本决定；不强求一个精确分数。
每项预先写成功、失败、无结论后的下一决定；成本高且不改变选择的测量可以停止。
筛选期允许单种子和有界小规模，确认期对少数关键比较增加种子、独立数据/长度和复现。
保留全部尝试及筛选理由，保留最终确认评估，避免只展示最佳种子或最佳checkpoint。
机制有效但当前慢、局部成功但规模失败、实验未完成要能在页面中分别表达。
