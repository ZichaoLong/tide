# 默认prefill与KV布局经验

本页承接[历史经验索引](performance-lessons.md)。具体成本及资格必须引用固定提交的证据；
当前活动只见STATUS，失败/停止与重启条件只见ROADMAP。

| 经验 | 本轮落实 | 适用边界与独立检查 |
| --- | --- | --- |
| 调度阶段数不等于设备算子数 | 已就绪、history_independent区域跨时间合批；KV实际槽拼接/gather、整批可见性和正支持 | 保留Next因果采用及历史依赖后备；一般端口/反馈/历史VJP检查 |
| 沿时间和sample一起合批 | 同一区域一次消费多个time/sample frame，查询跨不同缓存长度合并投影 | 不依赖预知选择、模型名称或节点阈值；记录region batch及snapshot bucket |
| LH的批量读/梯度回收可以借鉴，时钟不能照搬 | 保持原始int64时间；没有接收事件时间压紧 | 大于2**54时间、过期/稀疏记录和独立状态根 |
| 连续存储不等于完成packing | 真实gather/矩阵批替代逐行nonzero/布尔索引；未消除所有私有根装配 | 按算子和完整步测量，不从减少kernel数推断速度 |
| 填充可能改变数值稳定边界 | 忽略项不进入投影；Attention以首个正支持值为中心 | 1e30被忽略首值与接近的正支持值反例检查VJP；不只对照forward |
| 局部合批可以放大接近零的梯度差异 | packed-v2保留evidence逐行投影/归一化 | 原dense-v1见证与容差保持；局部修复不证明全部FP32整图等价 |
| 不同预热更新会破坏受控对比 | 预热后重置模型/optimizer，并记录初始和测量前参数hash | 旧continue流程保留具名选项；实际Full/消息和独立正确性仍分列 |
| 默认策略应依据能力 | auto选择KV packed-v2，其他执行配置保留原路径 | 新执行身份、实际逐节点选择、显式legacy/v1/v2复现；同模式精确恢复另验 |

32MiB仅是合并多行的估计目标，单行可超过；不称为峰值内存上限。
尚未做跨sample/time的全部私有KV写投影合批。该层涉及相同参数/相同输入的计算共享、
独立输入None根、版本和累加顺序，必须根据新profile占时决定下一边界。
不能凭buffer连续就声称低垂果实已全部完成，也不能用小图CPU/NPU资格外推大图或resident。

开发检查已经覆盖214通过、2个保留的v1数值xfail，以及40项配置/导航检查；这些不是固定提交资格。
实现提交后补充正式构建/安装/三客户端与实际成本证据。原始LH9B口述及本仓库实测在
[代表历史表](prefill-regression.md)分别定位；用户已确认口述记录，grad列阶段歧义不擅自填补。
