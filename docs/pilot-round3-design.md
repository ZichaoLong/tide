# 第三轮：首轮大规模模型搜索设计

本页区分用户已确认的要求与待冻结的建议。用户已同意将初始化验收/选参与正式训练拆成两个阶段，并接受阶段A需要修复时阻断阶段B。具体执行顺序、失败处置、数量/资源上限及保留规则已整理为[第三轮执行计划](pilot-round3-plan.md)，按最新指令等待用户授权后统一执行。尚未合入上游、修改实验实现或启动后台队列；以下具体配方和任务清单仍需准备阶段冻结。

## 已确认的要求与授权

- 至少200项不同模型任务。batch、LR的调参组合不计作不同模型；种子、分段接续及恢复重放也不用于凑模型数量。
- 每个模型的正式任务需达到10M token曝光。正式训练前可做有限自动调参，随后自动选择配方。
- 增加Transformer与MoE对照，覆盖同参数量、同活动预算/活跃比等问题，对照享受与Tide相同的调参待遇。
- 用户已同意将本地Shannon cap修复及相关回归合入上游，要求先记下、后续统一执行。该授权保留，不因切换线程再次请求；执行时核对上游最新状态，保留其用户修改，不强推。
- 上游合入和下游接入后，后台流程应自主完成调参、选参和正式训练。本机资源均可用于本任务；实际NPU使用遵循协作队列准入，按当时可用资源派发。
- 用户允许提交并交接后退出监控。届时验证真实服务/cgroup、记录查看与停止入口后交接，不必由当前会话监控到整轮结束。
- 阶段A存在需修改实现的问题、原因未明的资格异常或整批门槛未通过时，阶段B保持关闭。保留证据并释放资源，用户可之后唤醒助手检查和修复；后台程序不自行改代码或放宽门槛。当前先制定执行计划，得到用户后续授权后统一执行。

此前的“24个模型×3个LR×3个种子=216项”只有24个模型，不满足本次要求，不能直接执行。

## 模型计数与覆盖建议

建议以216个不同Tide模型作为主体，Transformer/MoE对照另列；这是保守覆盖用户要求的建议，尚不是已冻结任务表。

模型身份按有效拓扑、规模、记忆、接收、分配、参数归属、活动预算、时钟和读出契约规范化。相同有效函数/参数化的别名合并，例如无Hub时X与K、X_reverse与S。初始化配方、batch、LR、seed、线程、packing/backend及checkpoint设置不进入模型去重键。新增归一化或改变计算语义属于模型/实现变化，不能作为初始化调整隐去。

用覆盖设计选择合法组合，覆盖FC、Lattice、Exchange、Multiscale Settle/Timed；K/S/X/X_reverse；quad/Shannon/pool；窄KV、仅记忆共享、整体共享、接收形式、活动预算以及多个总容量档。主消融保留仅改变一轴的配对；另选有依据的交互组合，避免把全部选项作无约束笛卡尔积。

具体候选清单需经过有效图去重、静态合法性、实际参数计数和入场容量测量后冻结。模型数量、合法但未能运行的配置、实际完成模型数量分别报告，不以调参重试或种子填补缺口。

建议每条正式轨迹固定12,582,912个参与next-token loss的外部token，严格超过10M；padding、恢复参考、重放与Timed内部tick不计入。216个主体模型单种子正式曝光即2,717,908,992 token，调参、对照及重复种子另加。

## 对照与活动量口径

当前实验适配器只有Tide与稠密Transformer，尚无MoE。MoE需新增实际稀疏专家派发的decoder基线及对应梯度、状态、训练和恢复检查，不把全专家计算后mask当作稀疏执行。

| 对照 | 匹配目标 | 解释 |
|---|---|---|
| 稠密Transformer，总参数匹配 | 相近实际总参数量 | 比较同总容量的质量与成本 |
| 稠密Transformer，活跃参数匹配 | 相近每token实际活跃参数量 | 比较相近活跃参数预算；总容量通常不同 |
| MoE联合匹配 | 同时接近总参数量与实际活跃参数量/比例 | 包含共享Attention、router、共享专家等常驻部分 |
| 等计算/时间辅助比较 | 实测FLOPs、卡时、吞吐或达到目标NLL的成本 | 不从参数量推断等计算量 |

稠密Transformer主干近全激活，不能同时匹配低活动Tide的总参数和低活跃比。MoE的top-k/E只是专家选择比例，Tide的Full或发送预算比例也不是整个模型的实际活动比例。

总参数按唯一Parameter统计，权重绑定只计一次；全模型和排除词表embedding/输出头的主干口径均报告。活动量按每token实际参与计算的唯一参数统计，覆盖Tide接收、记忆准备、评分/区域网络及Full，覆盖MoE共享部分与选中专家。不能从梯度非零数推断实际活动；同一参数重复使用的次数、FLOPs、padding、状态读写和路由/派发成本另列。

建议在固定校准样本及有限调参中的规定测点采样活动量，按冻结的匹配算法选择对照后保持对照配置不变；正式训练继续报告活动分布与匹配偏差。最近合法配置不满足阈值时标为未匹配，不放置无效参数凑数。参数/活动档对照库可供多个Tide任务复用，但必须分别满足同一匹配口径、数据、配方和验证协议；不能靠少量对照覆盖全部不相容目标。

Transformer允许合理深宽/FFN组合；MoE允许专家数、top-k、专家宽度等结构选择。结构本身成为独立基线配置，调参预算按配置分配。主干与任务头、上下文、精度、优化器和辅助损失的差异明确记录。

## 初始化现状与验收建议

本次仅做源码核对，未进行新的初始化或学习实测：

- [Tide适配器](../pilotlab/models.py)只将词表embedding按标准差0.02初始化，主干沿用上游规则；输出头绑定embedding。
- 同一文件的Transformer将线性层/embedding按标准差0.02初始化，并将每层Attention输出与FFN下投影除以 `sqrt(2 * layers)`。Tide适配器没有另外施加图路径尺度校准；这不构成Tide初始化错误的证据。
- 当前上游 `src/tide/parameters.py` 的NodeLinear使用fan-in尺度，私有低秩适配器另有rank尺度；`src/tide/ssd_memory.py` 的 `a_log=0`、`dt_bias=-2`、`skip=rho=1` 等有各自含义。不能用全模型统一高斯重置覆盖这些参数。上游范围修复解决的数值求值问题，也不能替代初始化的学习验证。
- [现有worker](../pilotlab/worker.py)记录初始参数哈希、初始NLL、因果性及B1冷状态活动探针，但没有系统的逐层/区域激活、记忆状态、梯度和实际更新诊断。[现有选择器](../pilotlab/selection.py)只选LR，且要求batch等字段相同，不能直接承担第三轮联合选参。

初始化应成为有版本、可复现的训练配方。保留上游默认作为候选；根据实际诊断限定少数有依据的替代规则，关注输入/输出与残差尺度、共享参数累计梯度、区域评分/路由尺度及记忆时间常数。图聚合、有效串行路径和跨时间复用不同，不能把Transformer的层数缩放公式直接套到全部Tide拓扑。若使用数据相关定标，只能使用固定训练校准样本并记录定标结果，不能读取确认集。共享/绑定参数只初始化一次，checkpoint加载后不得再次初始化；记录配方版本、种子和初始权重哈希。

每个配置及拟使用的初始化规则先做3个预定种子的零步/少量更新诊断，学习筛选所用的2个种子在启动前指定，不因诊断结果换种子。诊断包括：

1. 在正式精度、上下文和拟用batch下，覆盖冷启动及跨chunk持续状态；观察激活/记忆量级、logits分布、初始NLL、裁剪前梯度、实际优化器更新和非有限值。接近零的参数另报绝对更新，避免相对更新比失真；初始NLL与 `log(vocab_size)` 的关系只作尺度诊断，不设相等门槛。
2. 检查Tide接收、Full、分配边界和路径参与度，MoE专家负载、router梯度及容量丢弃。结合声明的稀疏预算判断异常塌缩；不要求所有节点/专家每步都有非零梯度。不能用持续强裁剪、额外epsilon/floor或强制均匀路由掩盖问题。
3. 按预定覆盖表选代表配置做小训练样本拟合与关键模块梯度检查，区分实现错误、初始化失衡、优化器配方问题与学习缓慢。loss下降本身不能证明全部模块正确；短期下降慢也不单独构成模型出局理由。

阻断条件包括出现非有限值、状态/离散契约错误以及已确认的梯度或实现错误。激活、饱和、更新比和学习曲线作为有上下文的诊断信号；阈值及有限处置在阶段A开始前冻结，不能事后改门槛凑通过率。初始化诊断曝光与成本单列，三类模型享受相同的额度和机会。

## 阶段A：初始化验收与有限自动选参

阶段A覆盖整批候选及对照，先暴露共性问题，再形成每个模型的独立配方。初始化、LR、有效batch、warmup等组成有限联合配方，不展开所有轴的笛卡尔积；同一模型的全部试验仍只算一个模型。

建议把此前单种子6Mi选参预算调整为双种子8Mi，以降低幸运初始化造成的误选。一个具体上限如下，尚需入场测量后冻结：

| 选参步骤 | 每个模型的学习曝光 |
|---|---:|
| 最多6组联合配方，每组2个固定种子，各先训练262,144 token（0.25Mi） | 3,145,728 token（3Mi） |
| 同一模型的前2组配方，各种子继续到累计1,048,576 token（1Mi） | 追加3,145,728 token（3Mi） |
| 按相同1Mi曝光处的双种子结果选配方，获选配方的两条轨迹继续到累计2,097,152 token（2Mi）做稳定性确认 | 追加2,097,152 token（2Mi） |
| 合计 | 最多8,388,608 token（8Mi），初始化微诊断及评估另有固定小额预算 |

使用独立选参集，在预定有效性条件内按双种子平均NLL选配方，同时报告两个种子的曲线、差异和失败。2Mi步骤验证获选配方，不把其得分与1Mi的其他候选混排；确认失败按预定规则标记，不临时扩大搜索或挑换种子。各级接续保持状态和学习率日程一致；建议使用正式长程日程按曝光token截取的前缀，避免每个短档单独退火造成不可比。较短筛选仍可能偏向早期学习快的配方，须保留曲线并在正式阶段检查排序变化。

同等调参待遇包括初始化候选机会、试验数上限、种子、token/验证预算和选参规则。各家族可以有适合自身的初始化规则与LR范围；MoE的router负载均衡等配方也在其同一有限预算内选择，不给某一路线额外隐含搜索。batch需先做有限容量/吞吐校准，记录microbatch、累积和有效batch，不能把B1诊断默认值延续为正式batch。

阶段A结束产生整批健康报告和冻结的选参清单，包含模型去重键、初始化规则、种子方案、训练配方、数据/源码身份、参数与实际活动匹配、失败项和资源预算。达到至少200个不同主体模型的入场数量并满足预定条件后，才统一释放阶段B。某模型短跑NLL横向落后不作为删除理由；无可行配方或数量不足必须明确报告，不能用种子/重试补数，也不自动添加未列入预算的模型。

执行计划获准后，两个阶段可在整批门槛通过时自动衔接，阶段边界不默认新增人工批准要求。若阶段A暴露的问题需要改变源码、语义、初始化规则或搜索空间，后台写入阻断状态并关闭阶段B，保留现有输入和失败证据、收尾释放资源；之后由助手另立版本并重跑受影响的阶段A证据后再放行。有限调参中按预定规则淘汰的配方与需要修实现的失败分开记录，具体放行与修复规则见执行计划。

## 阶段B：冻结配方后的正式训练

每个通过准入的不同模型均进入自己的正式任务，不能在低于10M时因横向NLL较差而淘汰大多数模型。正式任务从头初始化，使用未用于阶段A的预定种子，完成独立12,582,912个loss token（12Mi），不把调参曝光抵扣正式预算。由阶段A选择初始化分布/规则，不选择某个运气好的初始checkpoint；新的种子仍需做同一套早期健康检查。

阶段B保留低频激活/状态/梯度/更新、活动量、验证曲线和checkpoint监测，并覆盖长文档与持续状态。阶段A短跑不能证明12Mi训练一定稳定。非有限值、实现/状态错误等按固定规则停止并保留失败，有限重试不换配方或挑种子；普通质量差的有效模型仍完成规定曝光。学习资格与严格数值/恢复资格分开，原Shannon预检超差及原门槛继续保留。

首轮以广覆盖为主；可预先限定对代表性优胜配置及其匹配对照追加2个正式种子，重复不增加不同模型数量。追加选择规则、最多配置数和总任务上限需在启动前固定。最终确认集不用于初始化、选参或选择追加模型。

216个主体模型按上述8Mi选参加单种子12Mi正式任务计算，共4,529,848,320 token；完整预算还必须加入对照、重复种子、评估和入场检查。该建议替换此前6Mi选参/共4,076,863,488 token的估算；不能沿用此前216条LR/seed轨迹的资源估算。

## 自动后台流程与执行前缺口

准备阶段完成上游cap修复与相关回归，采用包含新范围修复的固定版本，并在独立冻结输入上进行下游接入；原第二轮输入、checkpoint和失败证据保持原身份。

流程为：固定准备输入 → 阶段A（整批去重/初始化准入、双种子有限调参、自动选参与确认）→ 整批报告/门槛及配置冻结 → 阶段B（正式训练、规定的重复确认）→ 终态完整性核验及报告。代码、数据、搜索空间、决策算法和预算先冻结；运行中产生的选择和解析后配置单独落盘、记录哈希，不改活动源码。服务需能只执行阶段A、从阶段A产物启动阶段B，以及在既定条件通过时自动跨越阶段边界。

执行前需补齐：

1. 明确目标token与完成判定，修复到train_seconds却可标completed的现有行为；未达曝光不得算完成。
2. 区分逻辑模型、调参试验、正式种子与分段/尝试身份；支持完整调度清单恢复、跳过已完成项和从完整checkpoint接续，重试次数有限。
3. 新增MoE基线和三路可核对的参数/活动量统计；保留独立小规模枚举与梯度检查。
4. 分开状态加载正确性、后续数值轨迹可复现性和学习资格；已定位后端非确定性不直接拒绝学习。确定性与精度策略绑定运行/checkpoint身份，原轮失败和门槛不改判。
5. 建立独立文章级选参/确认清单、训练验证曲线和低频训练态活动采样。
6. 两代可回退checkpoint、原子完成记录、预先约定的有界失败载荷留存，以及全轮输出/并发写入预算；既有失败证据不删除。
7. 实测新基座下代表配置的吞吐、峰值和checkpoint大小；重新核对quota、共享FS、CPU及可准入设备，固定全局卡时、deadline和资源停止条件。
8. 实现版本化初始化配方、共享/绑定参数单次初始化、分种子的健康诊断和整批阶段门槛；对续训禁止重新初始化，诊断保持训练RNG/数据游标不受扰动。初始化报告、联合选参、正式模型计数和失败原因分别落盘。

本机资源授权不构成独占事实或无上限资源预算。长队列使用脱离会话的background.slice服务，动态利用准入设备；可使用全部适用CPU资源，但按实测给worker线程和内存预算。服务自己完成推进、checkpoint、重试、停止及报告，不依赖助手在线。

交接需记录固定输入身份、服务、真实cgroup、日志、进度、停止/恢复命令、预算和剩余任务。用户已允许退出监控；提交后确认服务确实运行并可查看、可停止即可交接。自动生成报告属于结果整理，科学结论仍区分执行、数值、离散、恢复、学习及性能。
