# 第一轮试运行审阅与下一轮建议

第一轮在 2026-11-19 北京时间 19:47:23–20:19:17 完成，正式窗口 31.91 分钟，包含排队、初始化、训练、验证、推理、保存及恢复。40 项全部执行，39 完成、1 失败，无未启动或超时任务。环境与数据准备另计。[全部任务报告](pilot-round1-results.md)列出了每项训练、prefill、decode、参数量、内存、checkpoint、排队和实际工作耗时；[JSON](evidence/pilot-round1-20261119.json)保留原配置和逐字段比较。

本轮已能回答“小规模真实文本路径是否能执行、成本多大、固定队列是否可自动运行”，还不能回答“合理调参后的 Tide 质量是否接近对照”。模型采用共同 FP32 配方和学习率；参数量、完成更新数和 token 曝光不同。39 项小留出探针 NLL 均下降，仅是学习迹象。

主要观察如下。

- **数值与恢复：**核验 85,300 条训练步骤，共 43,448,832 token 曝光，均为不同任务的累计值。已记录 loss、梯度范数及步耗时有限，步数/token 数与结果一致。40 个初始化因果探针均在原容差内，其中 20 个精确；该检查不覆盖训练后的全部状态。39 项完成任务的保存数据、下一输入、RNG、私有状态及 logits 精确恢复，参数、优化器和裁剪后梯度均在 `atol=1e-5, rtol=1e-4` 内；仅 5 项的所有恢复类别均精确。模型参数最大绝对差约 `4.31e-6`。参见[测量审计](evidence/pilot-r1-measurement-audit.json)。
- **一个基座执行失败：**`npu-exchange-x-shannon` 在初始验证阶段报 `allocation multiplier did not meet the total constraint`，没有训练吞吐或恢复结果。CPU FP32 最小例子显示，上界经过 `exp(log(cap))` 后低 1 ULP，被误判成内部点，重建后总量残差约 `0.446319`，原容差约 `2.10e-6`；独立 Decimal 参考满足约束。相同 seed/样本的 CPU 整模验证通过，原 NPU 失败行未捕获，因此还不能将最小例子的具体触发位置等同于 NPU 原因。已保留[复现脚本](../pilotlab/diagnose_shannon.py)及[诊断证据](evidence/pilot-r1-shannon-scalar-diagnostic.json)，未修复或放宽基座阈值。
- **模块参与度需要按配置解释：**Timed-X singleton 的变化张量数为 152/158，最后一步 `S.summary/read` 的 weight/left/right 共 6 项无梯度。冻结源码显示，X 的 SSD 用于 Hub，singleton Hub 固定控制不消费描述分支；这能解释该观察，不表示整个 SSD 不可训练。结果没有逐参数的整轮未变名单。全部 5 个 CPU/NPU Timed 探针的选定输出空位均为 0，但内部逻辑槽仍有空位；它们不构成完整离散轨迹认证。参见[结构审阅](evidence/pilot-r1-singleton-coverage.json)。
- **一个实验层问题已在正式运行前修复：**SSD namedtuple 状态搬运一度丢失类型，导致恢复失败；修复后回归检查、NPU 接入与正式恢复通过。初始失败仍在 `.local/pilot-r1/preflight/`，修复后记录在 `preflight-v2/`。

下面是代表性训练吞吐。除另标注外，工作量为 B8/L64；数值包含采样/传输、前反向、裁剪、AdamW 和同步，排除 JSON 日志写入，前三更新不进入吞吐样本。它们是不同工作负载的成本，不能据此直接排名架构效率或质量。

Exchange-X 的 B 和 L 同时翻倍后，每步 token 数增加 4 倍，吞吐增加约 3.13 倍，训练 allocator 峰值从 1.17 GiB 增到 4.24 GiB。该对比值得后续分别固定 L、B 做容量校准；它不是单独改变 batch 的受控实验。全部 NPU 任务的训练 allocator 峰值为 0.15–6.16 GiB，不能视为驱动或父子进程合计 HBM 峰值。

并行执行峰值为 **9 个 NPU worker＋4 个 CPU worker**，使用物理卡 `0,2,4,5,7,8,10,11,14`，均由协作队列准入。本轮任务的 CPU 分配不重叠，但不是跨项目独占。没有单独运行/并发运行的配对测量，也没有同卡并发证据。

完成的 NPU worker 总耗时为 377–481 秒，中位数 451 秒；CPU 为 250–281 秒，中位数 255 秒。NPU 设备队列等待另计，最大约 519 秒。checkpoint 为 19.7–230.5 MiB，保存约 0.07–0.65 秒，新进程恢复约 4.9–16.4 秒。当前主要耗时不在保存文件。

本轮保留 39 个 checkpoint，合计约 3.00 GiB；整个正式运行目录约 3.02 GiB。终态时账号使用约 43.85/700 GiB，文件系统可用约 1,672.73 GiB。这是该时刻账户与共享文件系统的观测，不是后续批次可继承的配额保证。[资源核验](evidence/pilot-r1-resource-policy.json)还发现 `MemoryMax=256 GiB` 没有落实到实际 memory controller；放大作业前应补齐有效内存约束。

[终态审计](evidence/pilot-r1-terminal-audit.json)确认没有本轮活跃进程残留，32 个 NPU 队列请求均已终止，冻结源码/配置/数据、私有 Tide Python 源码与 39 份 checkpoint 校验通过。systemd 单元退出码为 1，反映一个任务失败；这不是未收尾或仍在运行。

目前可以交给脚本的部分是固定任务表派发、等待空闲设备、时限与磁盘检查、保存、单步恢复比较及汇总。**自动 HPO、指标驱动淘汰/晋级、持续断点训练入口尚未实现。** 数学约束失败、未接入损失的模块和有限数值差异仍需要针对性审阅，不能靠自动重试或降低阈值消除。

建议下一轮先围绕问题修复、成本校准和真正的多步接续验证，形成约 40–80 项、60–90 分钟的有限表，再决定广泛筛选规模。具体配置与预算在轮间对齐后固定。优先工作包括：

1. 在新的明确版本上验证 Shannon 边界与总量、梯度，并捕获原 NPU 失败行；相关失败路径不直接进入长期队列。外部仓库在未另行授权修改前保持只读。
2. 选择代表路径，对 batch、长度、线程和并发做配对校准，评估完整任务耗时分布；继续探索较大 batch 的有效吞吐。
3. 补齐多阶段训练和长程接续，再检验中断、恢复、晋级后的数据位置、随机数、优化器与私有状态。早筛阶段缩短训练预算，晋级任务加长曝光；哪些检查可减少频率需有覆盖依据。
4. 使用匹配 token 曝光及适当参数/计算量的对照，加大验证样本并加入必要种子，逐渐收拢质量候选。本轮不据小探针 NLL 淘汰架构。

假设持续有 9 张卡，下表是理想平均完整设备占用预算，尚未扣除排队准入、轮末保留时间或可用卡变化；它不是单任务硬时限。

| 200 | 81 秒/项 | 162 秒/项 | 324 秒/项 |

沿用约 450 秒完整成本，200/500 项约需 2.9/7 小时。缩短 `train_seconds` 且保留足够的 `wall_seconds` 可以降低平均成本；当前 worker 固定预留 180 秒用于收尾，不能直接将硬 wall 压到 129.6 秒。下一轮应以完整耗时分位数及调度模拟估计完成率，并把预计完成与保守保证分开。尚未启动下一轮或后续长队列。
