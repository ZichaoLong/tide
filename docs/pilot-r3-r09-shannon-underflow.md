# r09 的 Shannon 正权重下溢

2026-11-20，CPU 和原作业使用的 4 号 Ascend NPU 均复现了同一故障。r09 已包含此前针对可表示弱权重的修复。这次的数学解超出了 FP32 输出能保留的正数范围。[逐行数值、源码哈希和设备复现记录](evidence/pilot-r3-r09-shannon-underflow.json)

下文记录当日修复前的源码比较与实验原型。随后实例基座在公开 API 实现了显式正支持策略。用新基座完成的三个真实 AdamW 更新及同策略新进程恢复另见 [TL-REQ-007 验收](requests/TL-REQ-007.md)。

## 故障发生在区域分配

`multiscale_settle-d128-k-singleton7` 的 A2 任务精确加载 A1 的 262,144-token 检查点。在累计完成 1,255 步、321,280 token 后，下一次前向的区域 Shannon 分配触发正权重检查。保存的参数、私有状态和输入在 CPU 与单卡 NPU 上，均在第 9 次分配的同一组 23 个坐标复现。该调用有 2 个样本，每个样本 128 个位置，每个位置 2 个候选。[原始 worker 结果](../.local/pilot-r3/campaign-r09/round/tasks/multiscale_settle-d128-k-singleton7-43b1716b2d-a2-2026112001-r2/attempt-0/result.json)

以 NPU 上样本 0、位置 1 为例，分数为 `[-73.4206619, 32.3033752]`，两个候选的下界均为 0、上界均为 1，分配总量固定为 1。此时弱候选的 Shannon 解为

$$
p_{\mathrm{weak}}=\frac{1}{1+\exp(s_{\mathrm{strong}}-s_{\mathrm{weak}})}
\approx 1.21516\times10^{-46}.
$$

FP32 最小正次正规数为 `2⁻¹⁴⁹ ≈ 1.40130e-45`。按最近值舍入，小于半个最小单位 `2⁻¹⁵⁰ ≈ 7.00649e-46` 的正数会存成 0。本例分数差为 105.724，同样单位总量、两个候选时，舍入到零的临界分数差约为 103.972。NPU 上全部 23 个弱权重的高精度解都在 `9.26e-51` 到 `2.64e-46` 之间。即使完整保留 FP32 次正规数，仍然会失去这 23 个正发送者。冻结实现据此报错。[分配保护条件](../.local/pilot-r3/campaign-r08/frozen/foundation/src/tide/allocation.py) · [独立 Decimal 解和 FP64 梯度](evidence/pilot-r3-r09-shannon-underflow.json)

## 旧基座处理过同类下溢

11 月 9 日，基座提交 `2c11695c` 给 core-5 的 Shannon 区域分配增加了可选的 `positive-floor-v1`，交付版本为 `74e7bbd6`。实际 HB16 故障行有四个候选、温度 0.25、总量 1.9164364。其中一个候选饱和，其余三个分配剩余总量，最弱项为 `3.10588e-46`。它和 r09 的 23 个弱项都落在 FP32 舍入到零的区间。11 月 17 日，`c0d5e07b` 随执行器重写移除了旧包。r09 使用的 `src/tide/allocation.py` 保留了中间运算修复和严格报错路径，未移植这个可选策略。[旧基座交付](https://github.com/ZichaoLong/tide/blob/74e7bbd62341d2ccd382194a2c52ad4fea033665/docs/positive-support-policy.md) · [重写提交](https://github.com/ZichaoLong/tide/commit/c0d5e07baf433bb706bc4be97cb8749507502719) · [HB16 独立解](studies/allocation-support-v5.md)

旧策略用 FP32 **最小正次正规数** `δ = finfo.tiny × finfo.eps = 2⁻¹⁴⁹`。其中 `eps = 2⁻²³ ≈ 1.19e-7` 是 1 与下一个浮点数的距离，`tiny = 2⁻¹²⁶ ≈ 1.18e-38` 是最小正规数。旧求解器通过残差检查后，只给普通 Shannon 分支中上界为正、log 响应有限、已舍入为零的坐标补 δ。可表示的正值、零上界、零总量及全上界端点保留原值。若有 N 个候选，总补量须在 `64 × N × eps × max(原存储总量, 总量下界)` 内，上界也要复核。分配反向使用补前的 log 响应，接收聚合和 KV 使用存下的质量，不可表示的质量梯度仍会报错。[旧策略源码](https://github.com/ZichaoLong/tide/blob/74e7bbd62341d2ccd382194a2c52ad4fea033665/python/tidegraph/weighted/support_policy.py)

旧 CPU 验收中，strict 在 HB16 第 87 步复现故障，新策略完成第 87–94 步，逐步补值计数为 `[1,3,0,0,0,0,0,0]`。第 90 步保存后用新进程恢复到 94 步，模型、AdamW 状态、RNG、梯度和逐步 loss 逐位一致。FC16 的上下文重置评估在补 8 个坐标后完成 3,878 个预测目标。旧 NPU 证据覆盖算子和小型任务接入，采用 mixed-c 放置。HB16 的八个真实更新在 CPU 上执行，完整状态和梯度对照仍有有限超差。[下游验收结果](studies/positive-support-acceptance-results.md)

另一个历史实现也使用过更大的阈值。实验仓库 11 月 11 日的独立 core-5 筛选器在 `positive_exp` 中把 log 值截到 `log(finfo.tiny)`。它会抬高部分仍可表示的次正规数。r09 的区域分配走冻结的 `tide.region` 和 `tide.allocation`。[筛选器源码](../tide_lab/direct_semantic_ops.py) · [r09 调用链](evidence/pilot-r3-r09-shannon-underflow.json)

## 旧策略在 r09 的实际回放

在 CPU 和原物理 4 号 NPU 上，分别用了该设备捕获的 23 行分数。各条路径沿用故障行的候选上界和总量。[回放数据与源码身份](evidence/pilot-r3-r09-shannon-floor-comparison.json)

| 路径 | 前向结果 | 反向结果 |
|---|---|---|
| 整个旧分配器，开启 `positive-floor-v1` | 23 行的弱项都算成约 `5.96044e-8`，补值 0 次。旧求解器用普通 FP32 求和核对总量，强项为 1 时，加上这个弱项仍舍入为 1。 | 给弱项传入 `10³⁰` 的梯度，两个分数的梯度在 23 行全部为零。 |
| 仅在 r09 的支持检查前调用旧存储函数，沿用当前反向（CPU） | 23 行全部存成 `[δ, 1]`。当前求解器把 23 个强项都标为命中上界。 | 同一测试的分数梯度仍全为零，代表行把约 `−10³⁰` 的梯度传给了强项的上界。实数解中，强项是略小于 1 的内部解。 |
| 将旧存储函数用于 r09 的分配结果，按二候选闭式解分别求强、弱分数梯度 | 两端都仅在原 23 个故障坐标存入 δ，每行的另一坐标逐位保留。NPU 代表行的补值为真值的 11.53 倍，各行范围为 5.32 至约 15.13 万倍，每个坐标的绝对误差均小于一个 δ。 | 两个候选在实数解中都处于界内。使用补前的 log 权重，NPU 代表行两个分数梯度为 `[+1.21516e-16, −1.21516e-16]`。每端各测 23 行，两项分数梯度和总量梯度对 120 位 Decimal 参考的最大相对误差低于 `3.89e-6`。 |

用保存的模型、私有状态和输入作整批回放时，仅对上述单位总量、二候选行使用闭式分配和旧存储规则，其余行仍走冻结实现。CPU、NPU 都完成 10 次 Shannon 调用，仅第 9 次的相同 23 行需要补值。两端的 loss 分别为 `5.55780554` 和 `5.55780506`，CPU FP64 参考为 `5.55780559`。两个 FP32 后端各有 123 个参数张量取得有限梯度。单独将 δ 送入当前接收聚合，一个内容为 0.25 的单发送者在两端都返回 0.25，内容梯度为 1。此次共用一个故障 batch，优化器更新数为 0。[隔离回放脚本](../scripts/probe_r09_shannon_floor.py) · [记录](evidence/pilot-r3-r09-shannon-floor-comparison.json)

## 方案取舍

| 方案 | 能保留什么 | 代价与适用场景 |
|---|---|---|
| 当前 strict 加稳定求值 | 活跃约束判断、补偿求和、缩放计算能恢复本来可表示的弱项，之前约 `5.89e-8` 的真实例已通过。 | 最终写回 FP32 时仍受量程限制。适合保留为诊断和回归对照。 |
| **选择性补 δ，分配反向用补前斜率** | 保留稠密发送者、已有可表示值与结构零，消息仍是普通 FP32。在本次单位总量行只改一个弱项。 | 不同尾部会存成同值。若一次接收主要由这些尾部构成，归一化后的内容可能明显改变。推荐先作为当前稠密对照的显式数值策略移植。 |
| 将小值统一抬到 `eps` 或 `tiny` | 实现简单。 | `eps` 约为 δ 的 `8.5×10³⁷` 倍，`tiny` 是 δ 的 `2²³` 倍。直接 clamp 会改变可表示值，可能激活零上界、破坏总量。自动微分还会把阈值以下的局部导数置零。 |
| 合法的正背景混合 | 在原分配和一个满足相同角色上下界、总量的背景分配之间插值，可保持约束并让弱候选获得可控份额。 | 引入混合系数，改变正常行的分配和梯度。总量恰在端点或角色上界极小时，可供分配的空间仍有限。适合作为新配方比较。 |
| 有界评分 | 本例试用 `32 × tanh(s/32)`，CPU、NPU 同一 batch 前反向完成，最小正分配约 `1.18e-25`。 | 32 是试验值。高分差区域的评分和梯度被压缩，选参和质量需重新评估。 |
| FP64 或贯通的对数、尾数加指数表示 | CPU 全 FP64 保留了本例约 `9.26e-51` 的尾部。扩展表示在其量程内还可保留多个极弱发送者的相对比例。 | CPU FP64 适合作参考。若在加速器上保留尾部比例，分配、传输、聚合、注意力、私有状态、反向及检查点都要识别扩展表示。只在分配器内升精度随后转回 FP32 仍会得到零。 |

建议保留当前求解器，在求解所得的活动约束上增加显式补值策略。先用补前的 log 质量区分可表示项、真正下溢项、结构零和饱和项。尤其要保留强候选与弱候选的耦合，`1−p` 存成 1 时强候选也可能仍在上界内。随后在 CPU/NPU 上检查角色上下界、可变总量、舍入边界两侧、多弱项汇合、KV 读写与大上游梯度。用真实后继输入核对 AdamW 更新、私有状态和同策略的新进程恢复。将策略写入运行和检查点身份，旧 strict 状态按显式转换迁入。A 的恢复仍取决于这些接续检查。[旧方案对比](studies/shannon-numerical-options.md) · [FP64 和有界评分结果](evidence/pilot-r3-r09-shannon-underflow.json) · [本次补值回放](evidence/pilot-r3-r09-shannon-floor-comparison.json)
