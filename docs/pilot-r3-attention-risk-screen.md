# 修复与有限风险筛查：NPU 原生单支持梯度阻断

本次按用户授权执行了tiled残差修复、真实状态续接和有限风险筛查。筛查发现新的NPU自动融合路径数值问题，未达到扩大阶段A的条件，阶段B关闭。记录为[审阅JSON](evidence/pilot-r3-attention-risk-screen.json)。所有源码、数据、环境和旧任务修改边界保持；没有重标旧结果，没有改变原容差。

## 已修复的路径

单个正质量可见key的归一化输出等于该key的V，故Q/K导数以及归一化正先验导数严格为零。基座 `attention.py` 在有界query/key tile内计算精确正支持数量，并应用此恒等式；普通tiled的反传点积先减公共V锚点以减少消减。质量缩放模式仍保留 `min(sum(w),1)` 的导数，真实零质量key保留右导数。这里没有小梯度裁剪，也没有改变前向或状态格式。

CPU定向集合161通过、3原xfailed。最初的随机弱质量新夹具含独立FP64商式本身的近零消减及有限零先验右导数超差，原夹具/日志/哈希已保存在 `risk-screen-r01/initial-weak-witness.json`；后续夹具分离结构恒等式与病态点积，原阈值不变。该部分不能解释为全部弱质量算例已严格等价。

## 新阻断

NPU独立测试16通过、3失败，失败均由 `auto` 选择原生 `npu_fusion_attention_v2` 后产生。单key与5槽中仅1个可见正key的18项补测均保持同一冻结源码、输入、lr=0.001、eps=1e-8、零初始Adam矩和weight_decay=0。

- `auto`与显式`npu_fusion`的Q/K残差最高6.72×10⁻⁹，被Adam放大成最高4.02×10⁻⁴的参数更新。
- 归一化/质量饱和时，本应零导数的正先验也出现最高5.66×10⁻⁴的错误更新。
- 同输入的修复后tiled Q/K及归一化先验更新为精确零；未饱和质量的合法振幅导数仍非零。

这是精确结构恒等式上的反例，并具有实际优化器更新影响。本次没有改动原生融合VJP，也没有静默改变auto选择策略。该反例未量化旧训练中的触发频率、参数已有Adam矩的抑制程度及长期质量影响，因此不能据此作废全部旧选参，也不能宣称其无影响。已有的KV有限超差、Shannon恢复超差另行保留。

下一步应在支持元数据上修复或限定这个路径，再验证真实auto整模型和必要的性能/选参变化。不能仅把数值相近的loss或正常退出当成解除阻断的依据。
