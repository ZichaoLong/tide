# 2026-08-24：P0 随机初始化预训练阶段性结果报告

> 截止时间：2026-08-24 09:35 CST。
>
> 报告性质：阶段性报告。D0、M8、N8、S8、S4-D8、B4-D8 已完成；B8 训练失败；S16、B16 仍在运行，因此后两组的 1B 结果以后补充。

## 1. 这轮实验要回答什么

这轮实验不是从已有 Qwen 权重继续训练，而是只采用 Qwen3-0.6B 的模型结构和 tokenizer，从随机权重开始预训练。它主要回答四个问题：

1. 带固定 receiver 拓扑的 TIDE residual 分支，能否在真实预训练数据上稳定训练；
2. `selected-dispatch`（SD）和 `broadcast-observe`（BO）在相同昂贵计算预算下是否大致持平；
3. receiver 的上下文状态是否真的进入了预测，而不只是被维护却没有被读取；
4. 增加每处 receiver 数量或增加顺序路由深度后，是否出现路径集中、receiver 饥饿、长路径信用分配或数值失稳。

本报告先解释名称、结构和指标，再给结果。主结论保持简短，状态、路径、失败和性能细节放在后半部分。

## 2. 名称和结构

### 2.1 每个任务名是什么意思

- **D0**：普通 dense Qwen3 backbone；`0` 表示没有 receiver 扩展。
- **M8**：标准 Top-1 MoE 锚点；在四个 block 中把原 MLP 换成 8 个无状态专家。
- **N8**：No-state matched control；保留 always-on 原 block，再外挂 8 个无状态 residual receivers。
- **S8 / S16**：Selected-dispatch；每处有 8 或 16 个 receivers，只有被 Top-1 选中的 receiver Observe、Update 并执行 FFN。
- **B8 / B16**：Broadcast-observe；每处有 8 或 16 个 receivers，所有 receivers 都 Observe、Update，但仍只有 Top-1 receiver 执行 FFN。
- **S4-D8 / B4-D8**：每处 4 个 receivers，共有 8 个顺序排列的单层 receiver 插入位置，因此每个 Token 依次经历 8 次局部路由选择。`D8` 表示本实验的顺序路由次数为 8，不表示模型总共只有 8 个 Transformer blocks，也不表示局部拓扑递归了 8 层。

`receiver` 是拓扑中固定存在的候选分支。每个 receiver 有自己的 Observe 投影、私有状态和 `1024 → 3072 → 1024` SwiGLU FFN；router 只决定本 Token 激活哪个 receiver 的昂贵 FFN，不改变 receiver 与原 block 之间的固定邻接关系。

| 任务 | 插入或替换的 block（从 0 编号） | 每处候选数 | 状态写入方式 | 计划训练量 |
| --- | --- | ---: | --- | ---: |
| D0 | 无 | 0 | 无状态 | 1B Token |
| M8 | `6, 13, 20, 27` | 8 个 experts | 无状态，替换原 MLP | 1B Token |
| N8 | `6, 13, 20, 27` | 8 个 receivers | 状态旁路并冻结 | 1B Token |
| S8 / B8 | `6, 13, 20, 27` | 8 个 receivers | SD / BO | 1B Token |
| S16 / B16 | `6, 13, 20, 27` | 16 个 receivers | SD / BO | 1B Token |
| S4-D8 / B4-D8 | `3, 6, 10, 13, 17, 20, 24, 27` | 4 个 receivers | SD / BO | 300M Token |

### 2.2 Base block 怎样工作，M8 和 N/S/B 插在哪里

当前 base 模型是 28 个 decoder blocks（编号 `0` 到 `27`）组成的 Qwen3-0.6B。hidden size 为 1024；每个 block 包含一次 causal self-attention 和一个 `1024 → 3072 → 1024` SwiGLU MLP，两部分都采用 Pre-Norm 和 residual merge。

设第 $l$ 个 block 的输入，也就是上一个 block 的最终输出，为 $h_{l-1}$。原始 dense block 依次计算：

$$
a_l=h_{l-1}+\operatorname{Attention}
\left(\operatorname{RMSNorm}(h_{l-1})\right),
$$

$$
h_l=a_l+\operatorname{MLP}
\left(\operatorname{RMSNorm}(a_l)\right).
$$

$a_l$ 不是 Attention 模块的裸输出，而是“block 输入与 Attention 输出相加”之后的表示；$h_l$ 才是当前 block 完整执行后的最终输出。简化数据流如下：

```text
h[l-1]
  ├─ RMSNorm → causal self-attention ─┐
  └────────────────────────────────── + → a[l]
                                        ├─ RMSNorm → SwiGLU MLP ─┐
                                        └──────────────────────── + → h[l]
```

M8 直接把指定 block 中的原始 MLP 替换成 Top-1 MoE。router 和被选 expert 读取的是 $\operatorname{RMSNorm}(a_l)$：也就是当前 block 的 Attention residual merge 之后、再经过 RMSNorm 的表示，而不是 Attention 模块的裸输出。每个 Token 只执行 8 个 experts 中的一个，原 dense MLP 不再另行执行：

```text
a[l] → RMSNorm → Top-1 router → 一个 expert → residual merge → h[l]
```

8 个 experts 在初始化时都复制同一个原 MLP，因此选择任何 expert 都保持原始函数；本实现不设 expert capacity 上限，也不丢 Token。

N/S/B 的位置不同。它们先让当前原始 block 的 Attention、dense MLP 和两次 residual merge 全部执行完，再把一层 receiver residual 分支接在 $h_l$ 后面：

```text
h[l-1] → 完整原始 block → h[l] → N/S/B receiver 分支 → 下一个 block
```

因此，N/S/B receiver 的输入是**当前 block 的完整最终输出**，不是上一个 block 的最终输出。它在空间位置上位于当前 block 与下一个 block 之间；对最后一个 block `27`，则位于该 block 与模型最终 RMSNorm 之间。原 dense MLP 在 N/S/B 中始终执行，receiver FFN 是额外的 residual 计算。

| 比较项 | M8 | N/S/B |
| --- | --- | --- |
| 新模块的位置 | 当前 block 内原 MLP 的位置 | 当前完整 block 之后 |
| 原 dense MLP | 被替换，不再执行 | 保留并始终执行 |
| 新模块输入包含当前 Attention 的结果 | 是；Attention residual merge 后再 RMSNorm | 是；还进一步包含当前原 dense MLP 的结果 |
| 结构性质 | 替换式 Top-1 MoE | 追加式 Top-1 residual receivers |

所以 M8 是学界常见 Top-1 MoE 的训练锚点，但不是 N/S/B 的严格状态对照。判断“有无状态”的直接对照是 N8 与 S8；判断“未选 receiver 是否也写入状态”的直接对照是 S 与同宽度的 B。

### 2.3 N、S、B 的共同前向过程

设原 Qwen3 block 的输出为 $b_t$，先形成当前公共消息：

$$
m_t=\operatorname{RMSNorm}(b_t),\qquad
p_t=\operatorname{softmax}(W_r m_t),\qquad
a_t=\arg\max_i p_{i,t}.
$$

$a_t$ 是当前 Token 唯一执行昂贵 FFN 的 receiver。对收到消息的 receiver $i$，先观察并更新 128 维私有状态：

$$
o_{i,t}=\tanh(W_i^{\mathrm{obs}}m_t+b_i),
$$

$$
s^+_{i,t}=\lambda_i\odot s_{i,t-1}+(1-\lambda_i)\odot o_{i,t}.
$$

$\lambda_i$ 是可训练的逐维保留率，初始为 0.99。直观上，状态一开始每次保留约 99% 的旧摘要、写入约 1% 的新观察。

三种 profile 的差别只有状态是否存在、谁收到消息：

| Profile | 哪些 receivers Observe / Update | 哪些 receivers 执行昂贵 FFN |
| --- | --- | --- |
| N | 无；状态参数仅为匹配初始化而保留、冻结并旁路 | 只有 $a_t$ |
| S | 只有 $a_t$ | 只有 $a_t$ |
| B | 所有固定 receivers | 只有 $a_t$ |

在 S/B 中，被选 receiver 读取更新后的状态：

$$
z_{a_t,t}=m_t+W^{\mathrm{state}}_{a_t}s^+_{a_t,t}.
$$

N 则直接使用 $z_{a_t,t}=m_t$。最后三者都执行同样的固定 residual merge：

$$
e_t=\operatorname{FFN}_{a_t}(z_{a_t,t}),\qquad
h_t^{\mathrm{out}}=b_t+p_{a_t,t}e_t.
$$

简化伪代码如下：

```text
b = original_block(hidden)              # always-on backbone
m = rms_norm(b)
p, active = top1_router(m)

if profile == S:
    state[active] = ema_update(state[active], m)
if profile == B:
    for receiver in all_fixed_receivers:
        state[receiver] = ema_update(state[receiver], m)

z = m                                   # N
z = m + state_projection(state[active]) # S / B
delta = receiver_ffn[active](z)          # 每处仍只算一个 FFN
hidden = b + p[active] * delta           # fixed merge
```

状态按“序列 × 插入点 × receiver”隔离，在每条 512 Token 序列开始时清零，不在不同训练样本之间共享。因此本轮验证的是序列内部上下文状态，不是跨样本或超长上下文记忆。

## 4. 指标和表格怎样读

- **Validation LM loss**：固定 validation 集上的自回归 Token 交叉熵，越低越好。困惑度 PPL 等于 $\exp(\text{loss})$，排序完全相同，所以主表只列 loss。
- **Probe**：validation 开头固定的 65,536 Token，仅用于状态和路由诊断；它不是正式 validation，也不参与训练。
- **`no-read` $\Delta$loss**：在同一 checkpoint、同一 probe 上继续正常更新状态，但临时禁止 FFN 读取状态。定义为“干预 loss − 正常 loss”。正值表示切断状态读取后预测变差，因此状态确实参与了预测；它不能单独证明状态改善了最终 validation 质量。
- **有效 receiver 数**：某一插入点路由分布熵的指数。若均匀使用 $R$ 个 receivers，值为 $R$；越小表示路由越集中。例如每处有 8 个 receivers 时，理论最大值是 8。
- **完整路径**：一个 Token 在所有插入点依次选中的 receiver 编号组合。例如四处各 8 个 receivers 的路径可写成 `(2, 5, 0, 7)`，理论共有 $8^4=4,096$ 种。
- **实际出现路径数**：固定 probe 中至少出现过一次的不同完整路径数量。只出现一次和出现很多次都各计一条。
- **有效路径数**：完整路径分布熵的指数。若 $K$ 条路径被完全均匀使用，它等于 $K$；若流量集中在少数路径，即使偶尔出现很多其它路径，它也会明显小于实际出现路径数。
- **相对初始化的路径变化率（churn from initial）**：对同一 probe Token，当前完整路径与初始化路径不同的 Token 比例。它不是“相邻训练 step 之间切换路径的比例”，也不表示路由一直来回抖动。
- **中位吞吐**：一个任务所有持久化 train 记录中 `tokens/s` 的中位数。它适合粗看成本，不是严格的硬件 benchmark。

## 6. 简短结论

1. **N8 与 S8 到 1B 仍然持平。** S8 比 N8 低 0.000293，没有清晰的最终质量增益；但后面的 `no-read` 实验表明 S8 确实在读取状态。
2. **已完成的同里程碑 SD/BO validation 基本持平。** 300M 时，B8 比 S8 低 0.000436，B16 比 S16 低 0.002496，B4-D8 比 S4-D8 高 0.000123。这些单 seed 小差值不应解释为谁稳定胜出。
3. **八插入点压力测试已稳定完成 300M。** S4-D8/B4-D8 的早期路径集中到 100M 时已经恢复，300M probe 中没有 receiver 完全饥饿。
4. **不能宣称 B8 已稳定到 1B。** 它在约 731M Token 出现非有限 loss；原因尚未定位。S16/B16 也尚未完成，当前报告不是最终稳定性结论。
5. **M8 锚点在本设置下没有优于 dense。** 1B 时 M8 比 D0 高 0.013086；N8/S8 比 D0 数值低约 0.043，但它们有额外 residual 参数和计算，不能把这部分差异归因给状态。

## 7. 补充分析

### 7.1 状态是否真的生效

为保证横向可比，下表统一使用各任务 300M checkpoint 的固定 probe。

| 任务 | 300M `no-read` $\Delta$loss | 直接含义 |
| --- | ---: | --- |
| N8 | 约 0 | 状态已旁路，符合预期 |
| S8 | +0.005518 | 切断状态读取后变差 |
| B8 | +0.028179 | 切断状态读取后变差 |
| S16 | +0.003611 | 切断状态读取后变差 |
| B16 | +0.024193 | 切断状态读取后变差 |
| S4-D8 | +0.018484 | 切断状态读取后变差 |
| B4-D8 | +0.046116 | 切断状态读取后变差 |

每个 matched pair 中，BO 的 `no-read` 影响都比 SD 大，说明 BO 中“未选 receiver 也持续 Observe / Update”的状态后来确实被读取。另一方面，N8 与 S8 的 1B validation 几乎相同，所以当前证据应拆成两句话：**状态被使用了；状态尚未显示清晰的最终质量收益。**

`no-read` 是对已训练模型的临时干预，会造成输入分布变化。它适合验证因果链是否接通，不适合单独估计“有状态训练比无状态训练好多少”。

### 7.2 receiver 和完整路径是否集中

下表同样统一使用 300M 的 65,536 Token probe。“理论最大路径”由每处候选数的路由深度次方得到。

| 任务 | 每层有效 receiver 范围 / 上限 | 实际出现路径数 | 有效路径数 / 理论最大路径 |
| --- | ---: | ---: | ---: |
| N8 | 7.84–7.94 / 8 | 2,948 | 722 / 4,096 |
| S8 | 7.77–7.91 / 8 | 2,645 | 580 / 4,096 |
| B8 | 7.68–7.90 / 8 | 2,678 | 529 / 4,096 |
| S16 | 13.08–14.54 / 16 | 10,159 | 2,568 / 65,536 |
| B16 | 13.11–14.46 / 16 | 9,349 | 2,313 / 65,536 |
| S4-D8 | 3.92–4.00 / 4 | 12,838 | 4,889 / 65,536 |
| B4-D8 | 3.91–3.99 / 4 | 12,506 | 4,652 / 65,536 |

300M 时每层所有 receivers 都至少被 probe 路由过一次，有效 receiver 数也接近各自上限，因此没有“某些 receiver 完全不工作”的饥饿现象。有效路径远小于理论组合数，说明完整路径分布并不均匀；这本身既可能是有用的路径专业化，也可能是过度集中，不能只靠一个集中度数字判断训练成败。

八插入点任务的有效路径数经历了明显的“先集中、后恢复”：

| 任务 | 初始化 | 10M | 100M | 300M |
| --- | ---: | ---: | ---: | ---: |
| S4-D8 | 3,997 | 390 | 4,631 | 4,889 |
| B4-D8 | 3,997 | 401 | 4,400 | 4,652 |

因此 10M 的强集中不是单调恶化。到 100M、300M，路径丰富度已经恢复并超过初始化值。

所有 routed 任务在 300M 时相对初始化的路径变化率都约为 99.96%–100%。这说明训练大幅重组了路径，而不是说明每一步都在持续切换路径；本轮没有记录相邻 checkpoint 或相邻 step 之间的路径 churn。

### 7.3 B8 的非有限 loss

- 失败时间：2026-08-23 04:23 CST；错误为 `FloatingPointError: non-finite loss at step 11159`。
- 最后一条持久化 train 记录：step 11150，730,726,400 Token。
- 最后一个完整里程碑 checkpoint 和正式 validation：300M。
- 失败前持久化的语言模型 loss、总梯度范数和 state norm 都是有限值，日志没有 OOM；因此目前不能仅凭现有记录把原因归为状态爆炸、路由崩溃或硬件内存不足。

这个失败已经足以否定“B8 在当前配置下稳定完成 1B”的说法，但尚不足以判断它是 BO 特有问题、偶发数值问题，还是某个数据 batch 与实现细节共同触发的问题。应先保留为未定位故障，不用其它任务的成功覆盖它。
