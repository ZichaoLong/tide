## 2. 为什么选 Qwen3-0.6B-Base

相比先前考虑的 `Qwen2.5-0.5B-Base`，`Qwen3-0.6B-Base` 更新，仍然是结构清楚的 text-only dense decoder，并且本机已经有经过文件校验的权重，也已有单芯 Ascend BF16 全参数 AdamW 成功运行记录。这能减少首轮环境与模型适配风险。

更近期的 `Qwen3.5-0.8B-Base` 于 2026 年发布，但它是带视觉编码器、Gated DeltaNet、周期性 full attention 和 MTP 的混合模型。它本身已经含有复杂循环状态，会让“新增 receiver 私有状态是否有效”更难归因。因此本日不选它；若 v0 在 Qwen3 上成立，再把它作为后续迁移对象。

真实运行必须把实际 checkpoint 文件哈希写进 manifest，不能只记录可变的模型名称。

## 3. 一个插入点怎样工作

设原 Qwen3 block 对当前 Token hidden 的输出为 $b_t\in\mathbb R^{1024}$。原 block 完整保留，它也是 always-on backbone。新增局部分支接在 block 之后：

```text
input hidden
    -> 原 Qwen3 block（始终执行） -> b_t --------------------------+
                                  |                                |
                                  +-> 固定 R0 / R1 / R2 / R3       |
                                      Observe / Update             |
                                      Top-1 receiver 执行 FFN       |
                                      其余 receiver 只保留状态      |
                                                   -> fixed add ----+-> output hidden
```

这里：

- **receiver** 是固定子节点槽位。每个 receiver 拥有 Observe 投影、128 维私有状态和自己的 FFN 参数。
- **Receive / Observe / Update** 是收到当前消息并更新小状态，四个 receiver 的邻接关系不随 Token 改变。
- **ExpensiveCompute** 是 receiver 内与原模型 MLP 同宽的 SwiGLU FFN。只有 Top-1 receiver 执行。
- **Emit** 是被激活 receiver 把 FFN residual 送到固定 merge；未激活 receiver 不产生 residual，也不继续传播。
- v0 只有一跳，所以 fixed merge 后立即回到共同 hidden；多跳留到后续实验。

## 4. 消息、选择和私有状态

### 4.1 当前消息与 Top-1 选择

先对 backbone 输出做 RMSNorm，得到当前公共消息：

$$
m_t=\operatorname{RMSNorm}(b_t).
$$

共享 router 只读取 $m_t$，不读取过去的 receiver state：

$$
p_t=\operatorname{softmax}(W_r m_t),\qquad
a_t=\arg\max_{i\in\{0,1,2,3\}}p_{i,t}.
$$

$a_t$ 是本次唯一执行昂贵 FFN 的 receiver。训练时加入一个小的概率均衡项：

$$
L_{\text{balance}}
=\sum_{i=0}^{3}\left(\overline p_i-\frac14\right)^2,
\qquad
L=L_{\text{LM}}+0.01L_{\text{balance}},
$$

其中 $\overline p_i$ 是一个训练 batch 内有效 Token 的平均 router 概率。它只防止一开始全部挤到同一 receiver，不使用设备负载或 batch 同伴改变单序列路由语义。

### 4.2 “衰减累积”是什么意思

receiver $i$ 在位置 $t$ 的动态状态记作 $s_{i,t}\in\mathbb R^{128}$。它不是模型参数，而是属于当前序列的运行时记忆。receiver 收到消息时，先形成新的观察：

$$
o_{i,t}=\tanh(W^{\text{obs}}_i m_t+b^{\text{obs}}_i).
$$

再把旧状态和新观察做指数移动平均：

$$
s_{i,t}^{+}
=\lambda_i\odot s_{i,t-1}
+(1-\lambda_i)\odot o_{i,t}.
$$

$\lambda_i$ 是限制在 $(0,1)$ 的可训练 128 维向量，初始化为 $0.99$。直观上，每次更新先保留约 99% 的旧摘要，再写入约 1% 的新观察；训练可以为不同维度改变保留速度。这就是本设置中的“衰减累积”。

实现中令 $\lambda_i=\operatorname{sigmoid}(\rho_i)$，从而训练时也不会跑出 $(0,1)$。Observe、状态累积和状态投影使用 FP32，投影回 hidden 后再转为 backbone 的 BF16。

如果 receiver 本次没有收到消息，则：

$$
s_{i,t}^{+}=s_{i,t-1}.
$$

状态按 `序列 × 插入点 × receiver` 隔离：新序列开始时清零；同一序列跨 chunk continuation 时必须保存和恢复；不同 batch 样本之间不能共享。v0 的训练样本长度固定为 512，样本结束即清零，不跨 optimizer step 保存神经状态。

### 4.3 两种传播 profile 唯一改变什么

令 $r_{i,t}$ 表示 receiver 是否收到并执行 Update，$c_{i,t}$ 表示是否执行昂贵 FFN：

| Profile | $r_{i,t}$ | $c_{i,t}$ |
| --- | --- | --- |
| `selected-dispatch` | $\mathbf 1[i=a_t]$ | $\mathbf 1[i=a_t]$ |
| BO | 对 4 个 receiver 都为 1 | $\mathbf 1[i=a_t]$ |

因此两组每个插入点都只执行一个昂贵 FFN。区别只是：未激活 receiver 在 BO 中仍看到当前消息并更新状态，在 `selected-dispatch` 中什么也不写。

v0 属于“selector 忽略 post-Update state”的配置。伪代码为了让两种 profile 共用同一路由，先计算 $a_t$；因为 router 只读取 $m_t$，这与先完成 BO Update、再使用同一个 $a_t$ 在数值上等价。

### 4.4 被选中后怎样读取状态

被选 receiver 先把更新后的状态投影回 hidden 维度：

$$
z_{a_t,t}=m_t+W^{\text{state}}_{a_t}s^{+}_{a_t,t}.
$$

然后才执行它自己的 SwiGLU FFN：

$$
e_{a_t,t}
=W^{\text{down}}_{a_t}
\left(
\operatorname{SiLU}(W^{\text{gate}}_{a_t}z_{a_t,t})
\odot W^{\text{up}}_{a_t}z_{a_t,t}
\right).
$$

新增输出以 router 概率加权后固定加回 backbone：

$$
h^{\text{out}}_t=b_t+p_{a_t,t}e_{a_t,t}.
$$

每个 receiver 的 FFN 输入、输出维度与 Qwen3 hidden 相同，中间维度沿用原模型 MLP 的 3072。$W^{\text{down}}$ 初始化为零，所以初始时 $e_{a_t,t}=0$，扩展模型输出与原模型相同；第一步应先给 $W^{\text{down}}$ 梯度，内部参数在输出投影离开零点后获得主任务梯度。

这条链说明私有状态怎样产生价值：receiver 在过去未被激活时写入消息；以后它被 Top-1 选中，ExpensiveCompute 通过 $W^{\text{state}}s$ 读取这些过去写入，进而改变 residual、logits 和 loss。

## 5. Reference 伪代码

```text
for each insertion point after the original Qwen3 block:
    b = original_block(hidden)              # always-on backbone
    m = rms_norm(b)
    probability, active_id = router(m)      # content-only Top-1

    for receiver i in fixed receivers [0, 1, 2, 3]:
        receive = (profile == BO) or (i == active_id)
        if receive:
            receiver_state[i] = ema_update(receiver_state[i], m)

    i = active_id
    z = m + state_projection[i](receiver_state[i])
    delta = expensive_ffn[i](z)             # only one receiver computes
    hidden = b + probability[i] * delta      # fixed residual merge
```

优化实现可以使用 mask、pack/scatter 或 scan，但必须与这段逐 Token reference 在 logits、状态和 route artifact 上一致。

## 6. 数据与训练预算

- 数据集：`HuggingFaceFW/fineweb-edu` 的 `sample-10BT` 配置，固定 revision `87f09149ef4734204d70ed1d046ddc9ca3f2b8f9`。
- 使用 Qwen3 原 tokenizer；文档之间加入 EOS，再按 512 Token 连续打包。
- 按固定文件和行顺序取前 100 万 Token 作为 validation、随后 1000 万 Token 作为 train；生成后的 Token 文件另记内容哈希。
- 单芯 NPU，micro-batch 4，gradient accumulation 4，每个 optimizer step 处理 8192 Token。
- AdamW：$\beta=(0.9,0.95)$、weight decay 0.1、gradient clip 1.0。
- Backbone learning rate 为 $10^{-5}$；新增 receiver、state、router 和 FFN 为 $10^{-4}$；前 5% steps 线性 warmup，之后 cosine decay 到初始值的 10%。
- 首轮每个训练组使用同一个 seed，各训练 1000 万 Token。只有出现正面信号后，才对 BO 与 matched `selected-dispatch` 补到 3 个 seeds。

上述 batch 是起始设置。若实际新增参数导致 OOM，只降低 micro-batch 并等量增加 gradient accumulation，保持每步 8192 Token 不变，同时在新的每日记录中说明。

## 7. 三个训练组与便宜诊断

| 组 | 设置 | 回答的问题 |
| --- | --- | --- |
| D0 | 原 Qwen3 continued pretraining | 不增加结构时，继续训练本身能改善多少 |
| S1 | 4 receivers、Top-1、`selected-dispatch` | 只有选中节点拥有历史时的 matched control |
| B1 | 与 S1 完全相同，仅切换为 BO | 未激活期间的状态写入是否有额外价值 |

D0 与另外两组的参数和 active FLOPs 不匹配，只是原 checkpoint 基线。首要因果比较是 S1 与 B1；两者必须具有相同参数、昂贵激活预算、初始化、训练 Token 和优化器设置。

B1 训练完成后直接做三种无需重训的验证干预：

1. `no-read`：保留状态更新，但把 $W^{\text{state}}s$ 置零。
2. `clear`：在指定位置清空 receiver state。
3. `shuffle`：在同一个 batch 内打乱不同序列的 receiver state。

如果这些干预不改变 logits 或 loss，就不能声称 BO 的延迟状态被实际使用。另做一个很小的 delayed-write/read 合成任务作为机制冒烟测试，但不把它当作自然语言 learning value。

## 8. 本轮输出和停止条件

每组至少输出：validation loss / perplexity、receive/update/active/read 次数、每个 receiver 的梯度覆盖、router 占用、状态范数与写入到读取间隔、训练吞吐和峰值显存。

按下面顺序决定是否继续：

1. checkpoint equality、save/reload 和任意 chunk continuation 先通过；
2. 零初始化分支能够离开零点并获得梯度；
3. B1 的状态干预可重复改变输出或 loss；
4. B1 相对 S1 出现 validation learning signal；
5. 前四项成立后，才进入多 seed、两层有界度扩展、flat MoE 和系统优化。
