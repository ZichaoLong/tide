# Develop Tide instances

The active product is the instance library defined by
[project scope](../../../docs/project-scope.md). It can remain the product across
many semantic cycles; the general foundation is a separately activated route.
Use [mathematical entry points](../../../docs/semantic-map.md) and the fixed
snapshot, then [architecture](../../../docs/architecture.md) to find current code.

Semantic correctness comes first, performance second. Keep B/L and compatible
node axes through reception, memory preparation, regional allocation, selected
Full, state and publication. Instance-specific layouts and backend implementations
are legitimate choices; share mathematical helpers where useful. Preserve
parameter sharing, private state, original int64 times and declared boundary
derivatives when changing a representation.

Choose small independent formula, solver or directional checks for affected
behavior. Include meaningful shared-parameter gradients, multiple updates and
continuation/restore cases when those paths change. Individual candidates and
useful interactions provide coverage without a Cartesian test matrix. Production
returns and tests serve the current public contract; universal action journals
and arbitrary internal gradient roots are not prerequisites.

[Precision](../../../docs/precision.md) separates FP32/BF16 targets, actual
storage/compute/accumulation policies and optional CPU FP64 diagnosis.
[Verification](../../../docs/verification.md) defines acceptance. Investigate
finite discrepancies with bounded witnesses; preserve the distinction between
rounding sensitivity and support, solver, causal or state errors. A plan to add
a dtype or backend is not evidence that it already works.

Keep current configuration/API instructions with the change and record tested
scope at its source identity. Task sequencing belongs in
[ROADMAP](../../../docs/ROADMAP.md), current facts in
[STATUS](../../../docs/STATUS.md), and execution/authorization rules in AGENTS.
