## 计时和状态边界

预热为独立零态的一次推理流，不更新参数，也不预热 backward/AdamW；正式第一段重新从零态开始。因此首个训练段包含第一次反向与 AdamW 初始化成本。每段 prefill128 分成两个 chunk64，接八个单位置 decode，Timed 再完整 flush。三段输入数值复用相同特征种子，但逻辑位置推进、历史继续，训练参数也每段更新；它们不是三次独立重复测量。
prefill 吞吐分母为 B×128；稳定 decode 跳过首个 decode，以剩余七次的 median 报时延、B×7/总秒数报吞吐。完整段吞吐为 B×136/complete_seconds，绝不用输出槽、消息或 tick 数充当输入 token。首主干输出为首个含正支持返回调用的完成时间，只有 chunk 粒度，不是 chunk 内最早 token，更不是带任务头服务的 TTFT。
完整训练包括 zero_grad、全部 chunk/decode/flush 前向、拼接和 FP32 标量 loss、跨整个段的 BPTT、foreach AdamW(lr=1e-4)、同步以及更新后私有状态 detach。下一段沿用该状态；训练段之间是显式截断边界。含梯度前向在段内保图、段间 detach，不执行 backward。构造、输入搬运、匹配审计、预热及 checkpoint 独立于正常计时。
device peak 在每段前 reset，但在段末有限值检查、state_memory 和外层 detach 后读取，所以涵盖这些未计入秒数的检查；不能称严格的纯计时区间峰值。CPU RSS 是整个子进程累计高水位，含构造和 Transformer 的初始 Tide 匹配审计。持久 state 同时列 payload 与去重 retained storage，后者保留 view 尾部，不等于峰值分配。

## 限制和复现

本报告正式计时覆盖有限 408 个真实输入位置/样本和三次更新，检查点另用 64 位置执行一次恢复更新，不是无限连续运行、质量训练或长时间漂移认证。Timed 每段主动 flush 后再继续，不能代替不中断的长 Timed 流。所有 loss 为机制用主干 readout 均方，含返回的 Timed 输出槽，无任务头。checkpoint 只使用 Tide 的公开 API；本矩阵不为 Transformer 提供恢复资格。
三段状态的 payload、retained storage、实际记录 dtypes 与 peak 都保留；BF16 政策仍保留 FP32 参数/主权重/敏感计算/梯度/AdamW 状态。连续 harness 未独立观测每个矩阵、梯度和 optimizer 实际 dtype，相关算子资格须结合独立精度与执行路径证据，不能只凭 BF16 字符串断言。

复现先依 [执行契约](../execution-flows.md) 检查配额、现有任务和协作队列，使用未占用的小写任务名、冻结提交及独立输出。以一组 NPU B1 为例：

```bash
python scripts/launch.py --name new-continuous-fc-k-npu \
  --revision 9a1f600f2b712aaebf28a1a689d864b2358a5fa6 --threads 4 --affinity 116-119 \
  --npu-count 1 --seconds 7200 --rss-gib 80 --queue-seconds 1200 -- \
  python -m benchmarks.programme --suite continuous --configs configs/fc-k.json \
  --device npu:0 --precision fp32 bf16 --threads 4 --batch 1 --length 128 \
  --prefill-chunk 64 --decode 8 --warmup 1 --steps 3 \
  --continuous-joint A B C D --checkpoints --child-timeout 900 \
  --output-dir '{run}/b1'
```

其余配置/B4、CPU 校准与依赖等候的精确命令、环境、资源、输出路径均见 JSON `runs[].launch`、`runs[].programmes`。原始结果位于对应 `artifacts/continuous-*/b*/`。证据检查仅重放小型 CPU 输入生成和统计，不重新运行模型或设备性能测量。
