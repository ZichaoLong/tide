# 主干候选的形成与取舍

本页保存从参考 LH、异时输出到 HB 各类候选的形成过程，供后续实验、选取配置和提出新变体时接续。重点是为什么形成某种构造、为此接受了什么代价，以及哪些问题仍待验证。后续意图与实验反馈可能改变连接、区域划分、局部函数或参数归属。

跨层的研究意图及其与语义的关系见[研究意图与探索路径](../memos/design/design-requirements-and-architecture.md)。本页在语义应用层记录具体回应：一个意图可由不同机制支持，一个机制也可以服务多个意图；候选可以覆盖不同的组合。保留这些联系，便于未来替换机制和提出新构造。

四份正典是上层语义锚点，局部教材规定函数；本页引用拓扑与实例的定义，说明选择理由和待实验判断的效果。阅读路线见[语义应用目录](README.md)，局部机制的进一步选择见[带权消息设计空间](../memos/design/weighted-message-design.md)。

## 1. 原始问题、意图相互作用与现在的分支

原始需求是一张真正允许长短加工并存的网络：一些任务可使用较早输出，另一些需要更深加工；长短通路在早期、中间和后期反复合作，持续输入时不要求每轮等全网结束。输入位置与逻辑时间分开，Tide 已为异时到达与持久状态提供相应语义。

同时希望分布式扩展、局部通信和稀疏参与，并让已知输入窗口的 prefill 有可预期的组织方式。这推动了严格区域分层的 HB 主候选；LH 继续探索有区内消息或反馈的一般情形。

这些目标是在讨论中相互推动的。例如，异时到达使输入间隔内的输出相位成为问题；相位覆盖和早晚合作共同推动跨层边设计。容量扩大又使分工与信息交换更困难，推动邻域、位交换和 hub 等不同方案；hub 与局部性、记忆成本及区域竞争结合后，进一步产生专用边族、分区和角色分配。一个需求可以引出多种构造，同一构造也可能同时回应几个需求。

| 需求及其相互作用 | 已形成的设计回应 | 接受的取舍与仍可变化的部分 |
|---|---|---|
| 快速输出与较长加工并存，并让长短路反复合作 | 多跨度 Timed、跨层连接与分散的中间汇合 | 允许不同输入位置的内容异时混合；短逻辑路径提供物理早出的机会，实际收益仍需测量 |
| 异时路径与稳定组织 prefill 同时考虑 | HB 主候选采用严格区域分层，并绑定有效的局部块构造；LH 保留区内连接及反馈探索 | 前者支持按区域拓扑序处理已知窗口；后者保留更一般的依赖，批组织更依赖具体运行 |
| 输入周期内的相位覆盖与各相位的信息合作 | 跨度 1／2、可选 4 的普通边，以及其他跨层交换 | 层数、边跨度和输入周期共同决定机会；相位齐全不保证每相位接收全部来源，更不保证信息有效 |
| 扩大容量，同时保留局部处理与中途交流 | 区域展开收拢、重叠邻域、Settle 位交换、可选 hub | 全量融合有重复加工与通信代价；交换过少则增加信息缺失和路由负担 |
| 少量摘要帮助普通通路协作，并控制通信与竞争 | DH／HH／HD 连接、有限探针、独立 H 区及角色上下界 | Hub 可能引入更大有限度数、特化实现成本和额外等待；无 hub、不同放置和分区仍有比较价值 |
| 合理内容维度、节点容量、较小参数规模与局部性 | 紧凑拓扑、三档参数归属、不同区内节点数和预算阶梯 | 各配置覆盖不同目标；共享减少独立权重自由度，并改变训练时的归约范围 |

因此，Settle 候选可以优先改善对齐计算中的交换，不必承担填满 Timed 相位的任务；LH 可以优先探索反馈与区内依赖，不必具有 HB 的严格区域分层性质。每个实例仍须满足其采用的数学定义和声明的条件。

| 分支 | 当前落点 | 主要比较 |
|---|---|---|
| 原 HB-Lattice | [既有拓扑](../topologies/hb-lattice.md)及实例保留 | 基础展开收拢、相邻层稀疏邻域、对齐时间 |
| HB-Timed | [多跨度图](../topologies/hb-multiscale.md)，单位边时延 | 严格区域分层且有多种路径时延 |
| Exchange-Settle | [分阶段位交换图](../topologies/hb-exchange.md)，普通通路为主、可选 hub | 为对齐计算设计的跨分支合作 |
| Multiscale-Settle | 与 HB-Timed 同样端点，跨度时延；输入周期 $D>M$ | 固定连接比较到达汇合方式 |
| 无特殊 hub | 删除 H 节点及 DH／HH／HD，保留完整 DD 子图 | 普通通路独立承担加工与交换 |
| LH-DAG | [双侧层次图](../topologies/lh-exploration.md)，区内边，无反馈 | 一般 TimedDAG |
| LH-PDG | 同一 LH 图加输出 hub 到输入 hub 的正时延边 | 有限切面与持续反馈 |

新的 HB 连接更细致，但不是原 HB 的数值等价替换；两者保留各自名称。多跨度连接并不只能用于 Timed：Settle 版仍有多尺度信息通路，但不能再借不同路径填充同一输入间隔内的全部输出相位。相同端点有利于控制结构差异，也可能使 Settle 版承担原本为频繁异时交换设计的冗余通信。旧 HB 提供另一种更直接的对齐基线；新的 Exchange-Settle 则让中间结果更早跨分支交换。这三种是空间图候选，不是三种 Settle 语义。

“无 hub 尚未完整绑定”曾指临时图已构造、正式局部组合尚未入库；并非它缺少可表达性。现在它直接使用[主绑定 K 或 S](hb-multiscale-weighted-message.md#2-两类记忆与三个主候选)，与含 hub 的图使用同样接口。

## 2. 扩大之后如何分工与合作

扩大之后，怎样让各部分既有分工，又有足够的信息合作，仍是真实问题。全量传播会增加重复加工和通信；过少交换可能丢失关键信息，并把过高要求交给路由。把每相位独占一条分支，再在少数节点集中融合，会重新形成压力集中。

这项问题与分布式扩展、局部化和稀疏化共同保留。今后发现另一种交换方式更好时，可以改变拓扑或模块；当前邻域、置换、hub 的组合提供可比较的已有方案，不穷尽可能的答案。

当前设计用三种可分开的机制回应：普通 DD 通路携带局部细节，邻域重叠和跨组置换让它们逐步合作；hub 通过 DH 收集压缩背景，通过 HH 跨组、跨层交换，通过有限 HD 探针送出钩子。这里预期 hub 可以只承担“摘要员＋钩子发送者”，细节和进一步加工留在其他通路。摘要可帮助下游依据已有细节和自身记忆进行选择。跨组把来自不同粗位置组的消息送到相遇处，融合由 Agg、记忆和内容函数完成；少量摘要并不自动补齐未收到的细节。

这里只手工设置 D／H 两类节点。主通路、邻域、跨组、跳层首先是连接类别；来源聚合可区别这些类别，不因此增加多套节点角色。结构规定可用信息和最低通信待遇，学习决定如何利用它们。纯学习角色更灵活，但不能保证学出必要的通信能力；完全手工专职更可控，也更容易限制泛化和增加算子碎片。当前折中是少量结构性角色、统一消息接口、同族可共享参数，暂不增加 hub 专用汇总函数。

在接收端，[局部自注意力候选](../local-semantics/weighted-message/architecture-learning-note.md#23-同刻消息的局部自注意力)让已到达的细节、背景和跨组信息在压成单个向量前相互影响。它为“摘要与钩子”提供另一项局部机制，普通节点和 Hub 都可采用；有效合作仍需拓扑把相关消息送到同一节点同刻。强度先验允许内容相关性调整读取份额，不把小强度解释为影响力的硬上限。全体候选的准备成本、Hub 实际同时到达数和早期响应时延应与质量一起测量，不能由 Full 的稀疏比例推断接收成本。

[接收尺寸绑定](hb-multiscale-weighted-message.md#11-接收自注意力的完整替换)保留来源残差基线，并列轻量与加宽自注意力。轻量取 $d_A=64$ 或 128、$p_a=d/8$，优先限制所有候选都要承担的准备工作；加宽取 $d_A=p_a=d$，用于考察汇聚前更充分的消息交互和逐条加工。内容宽度 $d$、接收投影宽度 $d_A$、逐条 MLP 的 $p_a$ 和 Full 的 $d_f$ 各有职责，不能仅凭总参数覆盖范围判断合理性。增加 Full 宽度不能恢复 Agg 已丢失的信息，加宽 Agg 也不会自动增加未到达的信息或历史检索能力。各档是否值得投入，需要结合信息保留、训练质量、实际扇入和准备时延比较；现有语义已能表达这些尺寸，实例绑定并不声称某档普遍更优。

同一位置的四个 hub 各收一部分、互相通过后续层传播；不是一份全局摘要的四次复制保证。它们可学到重复表示，也可分工，拓扑不能预先证明哪种结果。无 hub、稀疏放置、不同共享强度正好用于检查这种投入是否有价值。

## 3. Hub 组织、密度和内存

当前图示的每个非末层位置含一个 16 节点 D 区和一个 4 节点 H 区，末层只有 D；完整实例另给 32+4 配置。不是每个区域都有 hub。最早的 128+4 图把同位置 D/H 混在一区，二者的“位置”对应关系保持，分区发生变化。

三种分区的条件性排序仍是：独立小 hub 区优先，singleton 次之，混合区作为对照。group 可以在几个 hub 之间权衡发送，不让普通节点的大量描述直接进入 hub 的共同选择；singleton 适合更强调独立控制或独立响应的情形，可以排第一；mixed 提供同次共同选择，但也增加描述依赖和预算相互影响。固定通过时 group 的数值分配已经解耦，不应仅凭区域数量推断仍有竞争或必须物理同步。

部分位置放 hub 已有明确候选：在非末层按 $(\ell+p)\bmod2$ 交错保留，删除其余 hub 及关联边，普通子图不变。它用更少的摘要通路换较少节点与通信，不把剩余 hub 自动改为服务所有被删除位置。这里的全位置、半位置均指非末层；多跨度与位交换交互图均提供无 hub／全位置 group 的实际构图切换，半位置候选尚未接入面板。

末层 H 没有出边或输出端口，group／singleton 下也不参与末层 D 的分配，因此主图省去它们。在其余绑定保持时，这不改变保留节点轨迹与输出；mixed 下末层 H 可影响 D 的共同选择，不能宣称等价删除。构造参数 `terminal_hubs=True` 保留旧图的可复现性，三种分区的当前对照则可统一使用末层只有 D 的图。

Hub 常接收消息且较少，SSD 的固定状态有理由优先考虑；普通节点可以用有限 KV 保存细节。全 KV 与全 SSD 是两个统一算子对照。因此主候选收敛为 K／S／X 三组，其他既有模块继续作为研究目录；不要求实现全部笛卡尔积。较大的 hub 入出度是有限、已量化的代价，不能仅以“有界”一词掩盖实际扇入、投影和通信成本。

Hub 的“常亮”指收到消息且接收强度为正时保证正发送。既有讨论保留了固定通过、带下界及上界的候选；当前具体边界见[主绑定](hb-multiscale-weighted-message.md)，角色分配的函数定义在[区域教材](../local-semantics/weighted-message/region-allocation-learning-note.md#415-带角色上下界的二次分配)。缺席的 hub 不进入本次候选，混合区内的普通节点也不会因此取得 hub 的内容；它们可以只在彼此之间竞争。共同区域的有限预算约束是一种可接受的设计选择，其效果需要比较。这里没有加入自主心跳。

## 4. 异时混合与物理响应

假设输入间隔为 4，旧输入的时延 6 通路和新输入的时延 2 通路在同一节点相遇。它可能让新信号利用旧问题的深加工，也可能造成时间归属模糊、干扰或过时信息。Tide 定义其准确的聚合与历史顺序；优劣依任务与训练决定。没有必要先增加完整 token 来源集合。Pos 编码处理时间，不能把它误称为混合内容唯一的来源位置。

Settle 版把同源消息集中到一次作用，改变写入次数和竞争对象；它仍通过 KV／SSD 历史混合此前输入。严格区域分层保证的是已知窗口的区域求值顺序，不消除节点的状态依赖，也不把最短逻辑路径直接变成物理时延。

三种容易误解的等待见[实例 §5](hb-multiscale-weighted-message.md#5-精确求值与输出依赖)：较早状态更新、同区描述共同分配、上游选择决定消息是否存在。只等本次完整依赖；不等不存在的 Full，也不等与本输出无关的晚路。固定模型已经定义这些依赖，无需新增“快速输出就绪”规则。全窗口 prefill 与流式 decode 可以采用不同求值组织，只要保存相同参考语义。

Pronounce 仅作为语言任务的下游头提及；其聚合周期、输出组织及自回归接入由下游定义。其他任务头可以使用更高频率的输出，语言头的 token 周期不限制核心输出频率。无环图在持续输入下也可持续输出，有环图还可能在输入停止后继续活动。

## 5. Settle 的交换与三档参数绑定

Settle 同样需要信息交换。原 HB 的展开使分支获得共同背景，收拢融合后续结果，因此不能将其概括为只有缓慢邻域传播；它较弱的是不同分支的新中间结果和私有记忆在收拢前的交流。新位交换图在展开、宽段和收拢阶段都安排交换，宽段每轮改变一个区域位和一个节点位，以小固定度数扩大潜在合作范围。它不为填满异时相位增加捷径，宽度增加也不要求全局广播。

[Settle 三图共同实例](hb-settle-weighted-message.md)保留原 HB、多跨度 Settle 和位交换三种候选。若主要研究异时机制，优先同端点对照；若主要研究对齐计算的架构质量，优先位交换并用原图作简单基线。多跨度 Settle 仍有捷径和跨层融合，可能有效，也可能保留了对齐场景不需要的重复通信；这正是保留不同拓扑的原因。

比较分两个目的：同空间图固定局部与参数配置，观察到达结构改变聚合、写入和实际计算后，质量与时延如何变化；各自原生图则在相近资源、任务、可见前缀、读出能力和训练预算下比较整体架构。两侧分别训练，不能用未经适应的同一套权重直接推断架构质量。逻辑早到是机会，物理收益需测；同参数量不足以保证同计算量。

周期条件保持正典原样：层数 $M$ 包含首尾，Settle 取 $D>M$；新图 $D=M+1$，旧 HB 保持 $D=L+2$。Timed 中输入周期称 $T$。这项充分条件目前无须弱化，逻辑时间间隔也不要求物理设备等待同等时长。

[三档整体参数绑定](parameter-profiles.md)覆盖 Agg、来源嵌入、记忆、描述与评分、Full／FFN 及区域头。independent 使节点权重与区域头各自独立；region_shared 在区内共享大矩阵基座、保留节点适配器，区域头独立；layer_shared 保留同层同角色等相容节点的跨区域共享，并按层与区类型共享区域头。两个共享档只有共享范围不同。KV 的 mixed 区写入仍遵守每区一个基座，独立 KV 使用完整投影表示，状态始终私有。

HB 优先区域共享：区域扩宽同时增加独立基座，区内保留共同参数与节点修正。层级共享作为参数效率对照，独立参数作为节点自由度对照。共享梯度在所选组内汇总，按区域放置可避免区域档的跨区域权重归约，但消息反传和数据并行仍可能通信。FC 每层一区，两个共享档等价。单节点组不自动折叠适配器，三档参数量不保证严格有序；也不要求与 K／S／X 等所有轴做笛卡尔积。

## 6. 候选的覆盖范围与实验问题

当前候选分别覆盖异时合作、Settle 交换、区域组织、参数归属与一般反馈语义。主干规模表集中列 FC 和三种 HB 空间图，Multiscale 的 Timed／Settle 分别列项；LH、三种 hub 分区、半位置 hub 等仍有自己的定义，规模表并未枚举所有合法绑定。[离线交互公式面板](../explorers/backbone-atlas/README.md)展示其中适合逐节点阅读的图；面板是否提供切换不决定候选是否具有语义定义。

三组主局部记忆和三档参数归属控制近期实现范围，具体实验可挑选有解释价值的组合。常规 Transformer／MoE 可以作为下游实验参照；仓库中的显式残差 MoE 保持教学职责，不把它列为新增 Tide 主干系列。原教学实例与新比较实例各自保留自己的绑定。

后续真正需要证据的是：相位覆盖是否转化为有用输出，分区是否减少实际等待，共享／适配的容量是否足够，hub 摘要和普通局部细节是否互补，稀疏是否节约准备与 Full 的总工作，以及准确性与时延吞吐的折中。这些问题保留在设计记录，具体训练与系统实验属于下游。当前按具体配置说明预算比例，无需为约 3% 增加统一统计规章；候选以 Tide 数学为准，未复刻参考 LH 的旧 selector。累计 token 预算、自主唤醒、逐边载荷或动态检索均未接入当前主绑定。

### 6.1 描述关系与分配的主选择

主实例改用共同编码、候选 self_attention 和接收下界，意图是让节点和区域更直接比较本次接收与记忆，保障传播并允许内容决定筛选与放大。[完整绑定](hb-multiscale-weighted-message.md#12-共同编码与区域候选关系)统一取 $d_z=d/2$、每头 32 维、区域 FFN 宽度 d，一层区域块；节点编码沿三档共享，区域网络在前两档逐区独立、层级档按现有区域组共享。Full 与私有状态的接口保持，区域中间表示不成为新的消息载荷。

这份选择接受更多选择前工作，以取得候选间记忆关系的表达机会。原共同 query 较轻，encoded＋ind 也已有明确语义；是否值得加入关系块取决于真实质量、候选数及延迟。共同编码减少独立表示的数量，也可能让局部判断与关系判断争用有限宽度。机制理由与替代方案见[局部设计 §4.5](../memos/design/weighted-message-design.md#45-共同编码与候选之间的关系)；当前没有训练结论。

分配的近期主对照为 quad、约束 Shannon、pool。quad/Shannon 使用相同 received 下界、角色边界、区间总量和固定阈值；pool 为无约束求根的稠密参照。在规模表的 group 分区，三者仅替换 D 区，H 区保持有保底的角色 quad。LH mixed 的 Shannon 则同时作用于卫星和 hub；pool 若需保留 hub 待遇，先按已有定义拆区。旧教学实例保留其原绑定，新主表不额外枚举旧评分和旧下界作为必做基线。

拓扑、记忆、接收、评分和发送仍是分别有定义的选择位置。当前表收拢实现范围不意味着其他机制没有价值；可按新的问题替换某一项，再核对参数、传播与求值条件，无需穷尽组合。

## 7. 小规模独立参数与有序覆盖

[主干比较绑定](backbone-comparison.md)把 FC 与三类 HB 接到相同尺寸规则，保留 independent、region_shared 与 layer_shared（两个共享档默认秩 8，可选 4／16）。适配秩限制私有修正，不能看成无损压缩任意独立权重。独立参数下，几千节点在合理内容维度下很快超过 256M；降低 k 不减总参数。

候选集合共同覆盖规模与比例：普通区 n=8／16／32／64／128，预算只选合法的 1、2、4、8、16、32、64 及 pool，不为了接近 10% 或 30% 增添整数。小区不要求约 3%。原宽图、更多节点和更深图保留，超出 256M 也不自动缩小维度。

区域展开收拢提供容量增长的另一个可调因素，可以在区内协调范围固定时增加区域与独立参数基座。它本身不保证降低活跃比例。在当前比较绑定中，区域分配直接调节预算；消息是否到达、拓扑和实际内容还会影响准备与 Full 的真实参与。较大的区域允许更小的 k/n，也扩大一次共同选择的信息范围；不同区域将来可以使用不同预算，说明当次估算口径即可。quad 可产生稀疏但不保证给定活跃数，pool／Shannon 的稠密性也属于已知取舍。

增加两类紧凑轮廓：多跨度图允许层宽 1／2，继续反复交换、跨层和可选 hub；Exchange 把展开深度与平台轮数分开，让较少区域充分交换。它们保持严格区域分层及各自可核验的路径性质，但减少并行容量和冗余，不能声称与宽图同等效果。九层与十五层窄图提供从少节点到约 200M 的独立参数阶梯。扩大后如何分工并合作仍是设计动机，不能因为缩图而遗忘；实际信息利用、质量与系统效率由实验验证。

较大 hidden、较少总参数也是有意义的实验方向：可减少节点／位置，或选择区域／层级共享，保留足够内容宽度。代价分别涉及并行容量、独立基座数和节点私有修正能力。维度较大、节点较多的独立配置可以超过当前预算，仍可保留供后续扩大实验。当前 d=64 至 768、共享适配秩 4／8／16 和 256M 筛选线都是实例目录的选择，不构成所有未来变体的上层限制。

层宽、区内节点数、深度、边跨度和周期可在构造允许的范围内分别调整。17 层不是统一下限；浅层或紧凑图可以覆盖部分需求，增加跨度也会改变消息机会与通信成本。来源覆盖核对用于说明具体图的性质，无须将“每相位全部来源可达”提升为所有图的共同要求。

交互面板并列窄图与宽图，显示公式、逐节点来源覆盖与可重算主干参数；规模筛选和连接图切换分开。参数表按主周期明确列出 Timed／Settle，保留同空间图身份，参数单位为 M。它供选取与比较配置，不要求下游运行全部组合；具体字段见[比较绑定](backbone-comparison.md#6-交互与复算)。

## 8. 后续需求与新变体怎样接续

后续实验既可以调整已有配置，也可以暴露新的需求。例如，中间信息交换不足可推动新的跨组连接或摘要机制；hub 成本过高可推动更稀疏放置、不同分区或新的普通通路；异时混合的收益和干扰可能推动新的时间、记忆或来源处理。这里列的是可能的研究方向，尚未指定下一版方案。

新增候选时，说明它试图解决的具体问题、沿用和改变了哪些选择，以及优先覆盖哪些意图即可。小参数候选可以接受较少节点，局部通信候选可以接受较慢扩散，反馈探索可以接受不具备严格区域分层；这些取舍应与对应的参照一起保留。已有函数足够时，在拓扑和实例中完成连接、分区、时间、局部组合与参数绑定；若需要新函数或新的依赖关系，再由相应语义层给出定义。新构造应有自己的可复现说明，扩大旧 profile 的数值只覆盖其中一种情况。

研究意图、上层语义支撑、局部语义支撑、拓扑和局部组合分别说明到当前问题所需的程度即可。它们相互关联，但没有必要组成穷尽的乘积目录。一个有价值的意图可保留多条探索路径，现有机制的贡献也可能被其他机制替代或补足；选择某候选不等于已经确定了这项贡献。

本页持续保留设计缘由和替代选择，新的实验结论由下游记录并在需要时引用。一个方案不再是默认值时，其原先回应的问题仍可能有用；后续需求也可以新增或重新排序。记录应让研究者看清“当时为什么这样选、现在为何改变、可以与谁对照”，不把当前枚举冻结成最终架构，也不为每次探索增加繁重的评审规则。
