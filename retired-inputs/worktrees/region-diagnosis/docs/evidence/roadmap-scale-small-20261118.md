# ROADMAP 0.5B/1B 实际规模：单 NPU B1/L8，2026-11-18

四个实际模型与各自 A–D 基线的 FP32/BF16 推理、含梯度前向和完整 AdamW 已完成：
八个子项、120 行、360 个采样值，未出现失败或待测子项。这里是实分配/实更新，
不是 meta 参数估算；每个测点的输出、参数及存在的梯度均通过有限值检查。数值等价、
模型质量、长窗口、私有状态续接与恢复后更新并不由这些性能记录认证。

[压缩记录](roadmap-scale-small-20261118.json)保留所有样本、匹配目标/实际值/偏差、
初始与末次工作、真实存储、算子精度、源/配置/输入/参数 hash 和任务身份。源码/设施固定为
`e2a4d39104a006feec4525e534eadae4a94cde0d`，数学为
`4f5b9f20a4030d68ee66ae2d26e34659a5e37234`。

同精度完整训练时间，Tide/A–B 为 0.452–0.695×，Tide/C–D 为 4.673–68.358×。
Tide 相对 A/B 用时较短；A/B 是包含许多窄 Transformer block 的不同数学参照，不能据此判断模型质量。
短窗口下 FP32 optimizer 所需空间占主导，BF16 的完整训练峰值仍接近 FP32。

## 剩余范围与复现

本篇只覆盖约 0.5B/1B、B1/L8 的四个单卡实例和四类基线。没有长 prefill、增量 decode、
跨步私有状态训练、checkpoint/恢复更新，也没有跨卡、CPU 或 9B/17B 结论。更大模型的
容量/放置与实际测量由后续规模报告分别记录。这里的 finite 标签不消除既有数值超差。

按 [development](../development.md)准备环境，用新 identity/输出且重新按当次设备权限排队。
四组完整命令及资源界限在 JSON，例如 FC 0.5B：

```sh
python scripts/launch.py --name new-scale-fc-0p5b \
  --revision e2a4d39104a006feec4525e534eadae4a94cde0d \
  --npu-count 1 --threads 4 --affinity 84-87 --seconds 3600 --rss-gib 80 \
  -- python -m benchmarks.programme --suite scale --configs configs/scale/fc-0p5b.json \
  --device npu:0 --precision fp32 bf16 --threads 4 --batch 1 --length 8 \
  --warmup 1 --steps 3 --child-timeout 1500 --output-dir '{run}/results'
```
